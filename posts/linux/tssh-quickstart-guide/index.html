tssh 小白实操：安装、添加站点、tmux 批量登录、密码/SSH 密钥/UDP 登录、传文件与升级

tssh（trzsz-ssh）小白完整指南：Ubuntu/Debian、macOS、Alpine 安装；添加 SSH 站点；密码与 SSH 公钥认证；tmux 批量登录；UDP 弱网连接；trzsz 文件传输与升级。

本文以 tssh v0.1.27 为例，按“安装客户端 → 添加站点 → 密码/SSH 密钥登录 → tmux 批量登录 → UDP → 传文件 → 升级”的顺序操作。示例中的域名、用户名和密文均为占位值，使用前按自己的环境替换。

为什么要用 tssh#

tssh（全名 trzsz-ssh）是一个完全兼容 OpenSSH 的 SSH 客户端，服务器多了以后它能帮你：

  • 不用记 IP 和别名：运行 tssh 直接弹出服务器列表，输入关键字搜索，回车登录。
  • 配合 tmux 批量登录：在 tmux 里一次选多台机器，分屏 / 新窗口一起登录。
  • 记住密码：只能密码登录的服务器，把密码加密存进配置，以后免输。
  • UDP 模式弱网不掉线：配合服务器端的 tsshd，切换网络、休眠唤醒都不掉线（类似 mosh）。
  • 内置传文件：配合服务器端的 trzsz，一条命令上传下载，不用再开 SFTP 窗口。

本文覆盖：安装（Ubuntu / Debian / macOS / Alpine）→ 添加站点 → 密码登录 → SSH 密钥登录 → tmux 批量登录 → UDP → 传文件 → 升级，按顺序操作。

第 1 步：安装 tssh#

⚠️ 最容易抄错的值：macOS 上 Homebrew 的包名是 trzsz-ssh，不是 tssh。Ubuntu 装完命令是 tssh，macOS 装完命令也是 tssh（只是安装包名不同）。

Ubuntu（官方 PPA）#

sudo apt update && sudo apt install software-properties-common
sudo add-apt-repository ppa:trzsz/ppa && sudo apt update
sudo apt install tssh

⚠️ 报错原文：跳过 PPA 直接装会报 E: Unable to locate package tssh。必须先把 PPA 加进来。

Debian（手动加源）#

sudo apt install curl gpg
curl -s 'https://keyserver.ubuntu.com/pks/lookup?op=get&search=0x7074ce75da7cc691c1ae1a7c7e51d1ad956055ca' \
  | sudo gpg --dearmor -o /usr/share/keyrings/trzsz.gpg
echo 'deb [signed-by=/usr/share/keyrings/trzsz.gpg] https://ppa.launchpadcontent.net/trzsz/ppa/ubuntu jammy main' \
  | sudo tee /etc/apt/sources.list.d/trzsz.list
sudo apt update
sudo apt install tssh

macOS（Homebrew）#

brew install trzsz-ssh

⚠️ 报错原文：brew install tssh 会报 Error: No available formula with the name "tssh"。官方文档原话：「Homebrew 中命名为 trzsz-ssh，其他地方通常命名为 tssh」。

Alpine（下载静态二进制，官方没有 apk 包）#

Alpine 的软件源里没有 tssh（apk add tssh 会报 ERROR: unable to select packages）。官方在 GitHub Releases 提供静态编译的二进制，Alpine 直接能跑（已验证是 statically linked）。

① 查最新版本号：打开 https://github.com/trzsz/trzsz-ssh/releases/latest，记下版本号（写本文时最新是 v0.1.27）。

② 下载并安装（x86_64 机器，绝大多数电脑/服务器）：

先确认 uname -m 输出 x86_64。以下命令在 root Shell 中执行；若用普通账号且已配置 doas，给最后一条命令前加 doas：

wget https://github.com/trzsz/trzsz-ssh/releases/download/v0.1.27/tssh_0.1.27_linux_x86_64.tar.gz
tar zxvf tssh_0.1.27_linux_x86_64.tar.gz
install -m 0755 tssh_0.1.27_linux_x86_64/tssh /usr/local/bin/tssh

⚠️ 最容易抄错的值：

  • ARM 机器（如树莓派）要把链接里的 x86_64 换成 aarch64，文件名对应 tssh_0.1.27_linux_aarch64.tar.gz。下了不匹配架构的包，运行会报 Exec format error。
  • 链接里的版本号 v0.1.27 要和你查到的实际最新版一致，直接复制本文可能已过期。

验证安装（所有系统通用）#

tssh --version

看到 trzsz ssh 0.1.27 这类输出就成功了。报 command not found 时：Ubuntu/Debian 检查是否装完；Alpine 确认 /usr/local/bin 在 PATH 里（运行 echo $PATH 查看）。

第 2 步：添加站点#

tssh 的服务器列表读的是 ~/.ssh/config，和标准 ssh 共用同一个文件。有两种添加方式，小白推荐向导方式。

方式 A：向导添加（推荐）#

tssh --new-host

按提示填写（首次运行会先让你选语言，选 简体中文 回车）：

提示填什么举例
ConfigPath直接回车，用默认—
HostAlias给服务器起的别名，以后 tssh 别名 直接登录myvps
HostName/IP服务器 IP 或域名203.0.113.10
HostPortSSH 端口，默认 22，改过端口的填实际值2222
UserName登录用户名root
Password可留空（SSH 密钥登录时留空），或填密码（自动加密保存）—

填写时可以直接回车接受括号里的默认值，Ctrl+C 随时退出。填完后问 Would you like to log in now?，选 yes 立即登录。

添加完，~/.ssh/config 里会多出这样一段（填了密码的话）：

Host myvps
    HostName 203.0.113.10
    Port 22
    User root
    #!! encPassword YOUR_ENC_SECRET

💡 #!! 开头的是 tssh 扩展配置：标准 ssh 会当注释忽略，tssh 当成有效配置。这样同一份 ~/.ssh/config 两边都能用，不会报错。

方式 B：手写配置文件#

先确保目录存在，再创建或编辑配置文件：

mkdir -p ~/.ssh && chmod 700 ~/.ssh
nano ~/.ssh/config

然后写入：

Host myvps
    HostName 203.0.113.10
    Port 22
    User root

添加后怎么登录#

tssh            # 弹出服务器列表，方向键选择，回车登录
tssh myvps      # 直接登录别名
tssh root@203.0.113.10   # 没配别名时直接连 IP

tssh 列表界面里按 / 进入搜索，输入关键字回车锁定，再回车登录；按 ? 查看全部快捷键。

实战配置样例：直接抄作业#

以下是真实使用场景里最常见的几种配置形态（IP、密钥路径、密码密文均已脱敏，密文请用自己的 tssh --enc-secret 生成）。直接复制改改就能用。

样例 1：只有密码，最简单#

没有 tmux 自动会话，登录后手动操作：

Host pve
    HostName 203.0.113.3
    Port 22
    User root
    #!! encPassword YOUR_ENC_SECRET

样例 2：密码 + 登录后自动进 tmux 会话（推荐）#

RequestTTY force 强制分配终端，RemoteCommand 在登录后自动执行——这里会自动进入（没有就创建）名为 work 的 tmux 会话。断开后重连可回到原会话。

Ubuntu（bash）：

Host docker-ubuntu
    HostName 203.0.113.2
    Port 22
    User root
    RequestTTY force
    RemoteCommand tmux -u new-session -A -s work '/bin/bash -l'
    #!! encPassword YOUR_ENC_SECRET

Alpine（sh，注意 Alpine 默认没有 bash）：

Host alpine-vm
    HostName 203.0.113.33
    Port 22
    User root
    RequestTTY force
    RemoteCommand tmux -u new-session -A -s work '/bin/sh -l'
    #!! encPassword YOUR_ENC_SECRET

💡 不想用自动会话时，把 RemoteCommand 那行注释掉即可，登录就回到普通 shell。

样例 3：SSH 密钥登录 + 非标端口#

端口不是 22 时用 Port 指定；IdentityFile 指向本机私钥文件：

Host myvps-alt
    HostName 198.51.100.183
    Port 20789
    User root
    RequestTTY force
    RemoteCommand tmux -u new-session -A -s work '/bin/bash -l'
    IdentityFile ~/.ssh/id_rsa

样例 4：ed25519 SSH 密钥登录#

IdentityFile 指向私钥；没有配置 SSH 密钥时，tssh 会按服务器允许的认证方式继续尝试密码或交互认证：

Host coturn
    HostName 198.51.100.168
    Port 22
    User root
    RequestTTY force
    RemoteCommand tmux -u new-session -A -s work '/bin/sh -l'
    IdentityFile ~/.ssh/id_ed25519

样例 5：同一台机器两个用户#

同一个 HostName 配两个 Host，用不同别名区分：

Host app-user
    HostName 203.0.113.19
    Port 22
    User appuser
    RequestTTY force
    RemoteCommand tmux -u new-session -A -s work '/bin/bash -l'
    #!! encPassword YOUR_ENC_SECRET

Host admin-user
    HostName 203.0.113.19
    Port 22
    User admin
    RequestTTY force
    RemoteCommand tmux -u new-session -A -s work '/bin/bash -l'
    #!! encPassword YOUR_ENC_SECRET

样例 6：tmux -CC 模式（iTerm2 集成）#

-CC 是 tmux 的 iTerm2 集成模式（iTerm2 专用，普通终端用样例 2 的写法）。RequestTTY Yes 与样例 2 的 force 区别不大，都能用：

Host wgeasy
    HostName 203.0.113.5
    Port 22
    User root
    RequestTTY Yes
    RemoteCommand tmux -u -CC new-session -A -D -X -s 11 /bin/sh
    #!! encPassword YOUR_ENC_SECRET

样例 7：通过 SOCKS5 代理登录外网主机#

本机无法直接连接外网 SSH，但能访问一台 SOCKS5 代理时，可以让 nc 先通过代理建立到目标主机的 TCP 连接。下面的 203.0.113.232 和 192.0.2.6 是文档示例地址，必须替换成自己的外网主机地址和本机可达的 SOCKS5 代理地址；代理端口 1080 也按实际配置修改。客户端需安装支持 -x 和 -X 5 参数的 OpenBSD netcat。

Host us232
    HostName 203.0.113.232
    Port 22
    User root
    ProxyCommand nc -x 192.0.2.6:1080 -X 5 %h %p
    RequestTTY force
    RemoteCommand tmux -u new-session -A -s jay '/bin/bash -l'

这里 ProxyCommand 让 SSH 经 SOCKS5 代理访问 HostName:Port；SSH 登录认证仍使用本机已有的密钥或密码配置。可先运行 nc -h，确认帮助中包含 -x proxy_address[:port] 和 -X proxy_protocol；若系统的 nc 不支持这两个参数，需要安装 OpenBSD netcat。此配置只代理 TCP/SSH 连接，不会自动代理登录后的其它流量。

⚠️ 配置示例中的 YOUR_ENC_SECRET 只是占位文字，不能原样登录。运行 tssh --enc-secret 生成你自己的值后，再替换各示例中的占位符。

第 3 步：密码登录#

最简单：手动输密码#

添加站点时 Password 留空，登录时提示输密码，正常输入即可。

记住密码（推荐，加密保存）#

① 生成密文（在本地电脑运行）：

tssh --enc-secret

按提示在本机输入服务器密码，tssh 会输出一串值。下方 YOUR_ENC_SECRET 仅是占位符，必须替换成你刚刚生成的输出；不要把真实密码或输出贴进公开文章。

⚠️ 安全边界： tssh v0.1.27 的实现使用程序内置的固定密钥解码 encPassword。它只是可逆混淆，不是密码保险库；chmod 600 只能限制本机其他普通用户读取文件，不能防止拿到文件的人使用 tssh 解码。重要服务器优先用 SSH 密钥认证，不要把真实密文提交到 Git。

② 写进 ~/.ssh/password（tssh 专属扩展配置文件，标准 ssh 不读取它）：

nano ~/.ssh/password

写入并保存：

Host myvps
    encPassword YOUR_ENC_SECRET

⚠️ 密码里含 # 等特殊字符时必须用密文：明文会被当成注释，导致登录失败。

③ 收紧权限（防别人读你的密码）：

chmod 700 ~/.ssh && chmod 600 ~/.ssh/config ~/.ssh/password

之后 tssh myvps 直接进，不再问密码。

💡 记住密码后还是要求输入密码？服务器用的是 keyboard-interactive 认证，把 encPassword 换成 encQuestionAnswer1（密文不变）即可。

第 4 步：SSH 密钥登录（公钥认证）#

比密码登录更适合日常使用：私钥留在本机，公钥安装到服务器。

① 本地生成密钥对（只在第一次做）#

ssh-keygen -t ed25519

一路回车即可。会生成两个文件：~/.ssh/id_ed25519（私钥，绝不能给别人）和 ~/.ssh/id_ed25519.pub（公钥，要传到服务器）。

⚠️ 提示 Overwrite (y/n)? 说明你已经生成过密钥，按 n 跳过，直接做下一步，别覆盖旧密钥。

② 把公钥传到服务器#

ssh-copy-id -i ~/.ssh/id_ed25519.pub myvps

第一次会让你输一次服务器密码，之后就不再需要了。

💡 报 ssh-copy-id: command not found（个别精简系统）时，手动等效操作：

cat ~/.ssh/id_ed25519.pub | ssh myvps 'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'

③ 配置客户端默认用这把密钥#

~/.ssh/config 里对应站点加一行：

Host myvps
    IdentityFile ~/.ssh/id_ed25519

证书（SSH certificate）和普通 SSH 密钥是不同机制；本文示例使用的是普通 SSH 密钥。它可与密码登录并存：tssh 会按 SSH 配置和服务器允许的认证方式尝试。

第 5 步：tmux 配合批量登录#

tmux 是终端复用器，一个终端窗口可以开多个会话、分屏。tssh 在 tmux 里支持多选批量登录。Alpine 需要在 root Shell 执行 apk add tmux；普通账号且已配置 doas 时用 doas apk add tmux。

安装 tmux（一次性）#

# Ubuntu / Debian
sudo apt install tmux
# macOS
brew install tmux
# Alpine
apk add tmux

进入 tmux#

tmux

批量登录#

在 tmux 里运行 tssh 打开服务器列表，然后：

按键作用
Space 或 Ctrl+X选中 / 取消当前服务器（可以多选）
a 或 Ctrl+A全选当前页
o 或 Ctrl+O反选当前页
Ctrl+P分屏登录选中的机器
Ctrl+W新窗口登录选中的机器
Ctrl+T新 tab 登录选中的机器

选中多台机器按 Ctrl+P，tmux 会自动左右分屏同时登录，一台一台敲命令就行。

登录后批量执行命令再进 shell：

tssh -t -o RemoteCommand='uptime ; bash -l'

tmux 常用操作#

Ctrl+B 然后 d     # 挂起（detach）当前 tmux 会话，回来用 tmux attach
exit              # 退出当前分屏 / 窗口

⚠️ 常见坑：没开 tmux 直接按 Space 选不中服务器（列表会提示不支持多选）。先在 tmux 里运行 tssh 即可。

⚠️ Alpine 上 tmux 传文件卡顿 / 上传下载没反应：多半是服务器的 sshd 把 TCP 转发关了。在服务器上检查：

cat /etc/ssh/sshd_config | grep AllowTcpForwarding

如果输出 AllowTcpForwarding no，编辑 /etc/ssh/sshd_config，检查是否有针对该用户/地址的 Match 段；修改后按服务器系统重启 SSH：

# Alpine（OpenRC，root）
rc-service sshd restart
# Debian / Ubuntu（systemd）
sudo systemctl restart ssh

第 6 步：UDP 模式登录（弱网不掉线）#

原理一句话：tssh 先正常 TCP 登录服务器，在服务器上拉起一个 tsshd 进程，然后会话切换到加密的 UDP 通道。之后切网络、休眠唤醒、延迟抖动都不掉线。服务器不需要 root 权限，和 mosh 类似但支持 SSH 转发、ProxyJump 等功能。

① 服务器安装 tsshd（一次性）#

默认装到服务器 ~/.local/bin/：

tssh --install-tsshd myvps

指定安装路径（只有远端登录账号有该目录写权限时才用；例如以 root 登录）：

tssh --install-path /usr/local/bin --install-tsshd myvps

普通远端账号不要直接写 /usr/local/bin，会遇到 Permission denied；新手保留默认的 ~/.local/bin/。

⚠️ 安装路径含 ~/ 时必须加单引号，如 tssh --install-path '~/bin' --install-tsshd myvps。--install-tsshd 不支持 Windows 服务器和跳板机（除非用 ProxyJump 跳过）。 💡 手动指定版本 / 离线安装：--tsshd-version x.x.x 指定版本，--tsshd-bin-path /path/to/tsshd.tar.gz 指定本地安装包。

安装后在服务器检查版本，并确认 tsshd 的绝对路径：

~/.local/bin/tsshd --version
printf '%s\n' "$HOME/.local/bin/tsshd"

若输出 /root/.local/bin/tsshd，就把该路径写入客户端 ~/.ssh/config；普通账号的路径通常是 /home/用户名/.local/bin/tsshd。

② 客户端配置 UDP 模式#

~/.ssh/config 里对应站点写入下面两行。示例 Host 使用 root；如果远端用户不是 root，把路径改成刚才查到的实际绝对路径：

Host myvps
    #!! UdpMode yes
    #!! TsshdPath /root/.local/bin/tsshd

tsshd 装在 ~/.local/bin 时通常不在非交互登录的 PATH 里；设置 TsshdPath 可避免客户端找不到它。

③ 登录#

tssh myvps         # 已配置 UdpMode，自动走 UDP
tssh --udp myvps   # 或临时指定（默认 QUIC 协议）
tssh --kcp myvps   # 延迟敏感场景用 KCP 协议
tssh --tcp myvps   # 临时想走普通 TCP

④ 防火墙放行 UDP 端口#

tsshd 会在 61001~61999 之间随机挑一个空闲 UDP 端口。服务器有防火墙的必须放行：

# ufw（Ubuntu / Debian）
sudo ufw allow 61001:61999/udp

# firewalld（Fedora / Rocky 等）
sudo firewall-cmd --add-port=61001-61999/udp --permanent && sudo firewall-cmd --reload

⚠️ 典型故障：没放行 UDP 时，tssh 登录后马上掉线或会话无法建立。除了服务器本机防火墙，云服务器还要在云控制台的安全组/网络 ACL 放行相同 UDP 端口范围。先用 sudo ufw status 检查本机防火墙是否开启、规则是否在。

常用 UDP 参数（可选，按需添加）#

Host myvps
    #!! UdpMode yes
    #!! TsshdPort 61001-61999   # tsshd 监听端口范围，默认 61001-61999；支持 6022,7022 离散列表
    #!! TsshdPath /usr/local/bin/tsshd   # 服务器上 tsshd 的路径，不配则找 $PATH
    #!! UdpAliveTimeout 86400   # 断线超过该秒数（默认 86400=10天）会话结束，不再支持重连
    #!! UdpHeartbeatTimeout 3   # 断线超过该秒数尝试换条路重连，默认 3 秒
    #!! UdpReconnectTimeout 15  # 断线超过该秒数显示断线通知，默认 15 秒
    #!! UdpProxyMode TCP        # 网络禁止 UDP 时改用 TCP 传输（能通但更慢）

💡 断开后想自动重连：tssh -f --reconnect myvps（后台运行，断开自动重启进程重登）。注意 --reconnect 只重启登录，不会恢复原会话——要恢复原会话请用 UDP 模式 + RemoteCommand 自动进 tmux。

第 7 步：传文件（trzsz 上传下载）#

tssh 内置 trzsz 传文件支持，在 SSH 会话里直接上传 / 下载，不用另开 SFTP 窗口。

① 服务器安装 trzsz（一次性）#

tssh --install-trzsz myvps

默认装到远端登录用户的 ~/.local/bin/。只有远端账号有 /usr/local/bin 写权限时，才使用 --install-path /usr/local/bin；普通账号直接指定系统目录会报 Permission denied。

tssh --install-path /usr/local/bin --install-trzsz myvps

💡 注意：--install-trzsz 是在本地下载、安装到远端服务器，提示里的 /root/.local/bin 是服务器路径，不是本地，没装错地方。

② 配置服务器 PATH（必须做，否则找不到命令）#

安装到 ~/.local/bin 后，先在服务器上确认远端用户的 Home 目录，并让当前会话立即生效：

printf '%s\n' "$HOME/.local/bin"
export PATH="$HOME/.local/bin:$PATH"

要让 tssh 的登录 Shell 以后也能找到 trz 和 tsz，把 PATH 写入远端用户的登录配置文件：

touch ~/.profile
grep -qxF 'export PATH="$HOME/.local/bin:$PATH"' ~/.profile || printf '%s\n' 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.profile
. ~/.profile

如果远端使用 zsh，把文件 ~/.profile 改为 ~/.zprofile。安装到非默认目录时，把示例中的 ~/.local/bin 换成实际目录。

③ 上传 / 下载#

trzsz          # 上传：弹出本地文件选择框（仅限 tssh 会话）
tsz filename   # 下载：把服务器上的文件下载到本地

⚠️ 大文件 / 慢网络必加 -t 0：trz / tsz 默认 20 秒没动静就超时，传大文件要指定不超时：

trz -y -t 0        # 上传，覆盖已有文件，不超时
tsz -t 0 filename  # 下载，不超时

常见坑#

  • trzsz: command not found → 99% 是 PATH 没生效（回到第 ② 步）或不是用 tssh 连接的（普通 ssh 不支持 trzsz）。
  • 排查命令：echo $PATH、which trzsz。

第 8 步：升级 tssh#

升级前先确认当前安装方式和命令路径：

command -v tssh
tssh --version

Ubuntu / Debian（通过 APT 安装）#

sudo apt update
sudo apt install --only-upgrade tssh

macOS（Homebrew 安装）#

brew update && brew upgrade trzsz-ssh

Alpine 或手动安装的 Linux 二进制#

先到官方 Releases 确认最新版及 CPU 架构，再下载对应 tar.gz。下面以 x86_64 的 v0.1.27 为例：

wget https://github.com/trzsz/trzsz-ssh/releases/download/v0.1.27/tssh_0.1.27_linux_x86_64.tar.gz
tar zxvf tssh_0.1.27_linux_x86_64.tar.gz
install -m 0755 tssh_0.1.27_linux_x86_64/tssh "$(command -v tssh)"

如果当前命令安装在系统目录且当前用户无写权限，root 直接执行 install；已配置 doas 的 Alpine 普通用户在命令前加 doas，Debian/Ubuntu 普通用户则加 sudo。ARM64 包名中的 x86_64 要换为 aarch64。

验证：

tssh --version
command -v tssh

这只升级本机 tssh 客户端；服务器上的 tsshd 与 trz/tsz 是独立程序，需要分别按本文对应步骤更新。

第 9 步：常见问题#

现象原因 / 解决
E: Unable to locate package tssh（Ubuntu）没加 PPA，回到第 1 步安装章节
Error: No available formula with the name "tssh"（macOS）包名是 trzsz-ssh
ERROR: unable to select packages（Alpine）Alpine 没有 tssh 包，用下载静态二进制方式
Bad configuration option: UdpMode（用 ssh 时）标准 ssh 不认 tssh 扩展配置，给该行加 #!! 前缀
记住密码后仍要输密码服务器是 keyboard-interactive 认证，把 encPassword 换成 encQuestionAnswer1
列表里出现不想看到的条目该配置前加 #!! HideHost yes，或别用通配符当主机名
忘了服务器别名直接运行 tssh 打开列表，按 / 搜索
SSH 密钥登录失败检查服务器上 ~/.ssh/authorized_keys 与目录权限；公钥要追加到对应远端用户的 authorized_keys
tmux 里上传下载卡顿 / 没反应（Alpine 常见）服务器 sshd 配了 AllowTcpForwarding no，注释掉并重启 sshd，见第 5 步
trzsz: command not foundPATH 没生效或不是用 tssh 连接的，见第 7 步

查证方法#

tssh --version        # 查版本
tssh --list-hosts     # 列出所有已配置的站点
tssh --debug myvps    # 调试登录，打印详细日志（报错时用）
