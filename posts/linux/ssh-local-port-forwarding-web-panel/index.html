SSH 本地端口转发访问 Web 面板

使用 SSH 本地端口转发访问服务器上的 Web 面板，包含端口含义、SOCKS5 代理命令及转发被 sshd 禁用时的处理方法。

以下示例使用占位符，请替换为自己的服务器地址、用户名、SSH 端口、面板端口和私钥路径。

1. SSH 本地端口转发

在本地电脑执行：

ssh -i /path/to/private_key -p SSH端口 -N \
  -L 127.0.0.1:本地端口:127.0.0.1:面板端口 \
  用户名@服务器地址

保持终端窗口开启，然后在本机浏览器访问 http://127.0.0.1:本地端口。-N 表示只建立隧道，不打开远程 shell。

-L 中两个端口的含义

格式为 -L [本地监听地址:]本地端口:目标地址:目标端口。在上面的命令中：

  1. 本地端口 是本机 SSH 客户端监听的端口；浏览器访问 http://127.0.0.1:本地端口。如果本地端口被占用，可以换成其它空闲端口，并同步修改浏览器地址。
  2. 目标地址:面板端口 是从服务器一侧访问的目标。127.0.0.1 指服务器自身，面板端口 必须与面板实际监听端口一致。

两个端口可以相同，也可以不同。流量路径是：本机浏览器 → 本地端口 → SSH 加密隧道 → 服务器的 127.0.0.1:面板端口。

2. 通过 SOCKS5 代理连接

ssh -o 'ProxyCommand=nc -x 代理地址:代理端口 -X 5 %h %p' \
  -i /path/to/private_key -p SSH端口 -N \
  -L 127.0.0.1:本地端口:127.0.0.1:面板端口 \
  用户名@服务器地址

浏览器代理规则需将 127.0.0.1 和 localhost 设为直连。

3. 保存为 SSH 别名

写入本机 ~/.ssh/config：

Host my-panel
    HostName 服务器地址
    Port SSH端口
    User 用户名
    IdentityFile /path/to/private_key
    LocalForward 127.0.0.1:本地端口 127.0.0.1:面板端口
    # 需要 SOCKS5 时启用下一行
    # ProxyCommand nc -x 代理地址:代理端口 -X 5 %h %p

启动隧道：

ssh -N my-panel

4. 解决 administratively prohibited

该错误表示服务器的 SSH 策略拒绝端口转发。检查 /etc/ssh/sshd_config 及其配置目录，确保允许转发：

AllowTcpForwarding yes

AllowTcpForwarding local 也允许本教程使用的 -L 本地转发；yes 会同时允许本地和远程 TCP 转发。若配置中有 DisableForwarding yes，需移除该限制。

本场景通常不需要新增 PermitOpen；如果服务器已有该项限制，确认其允许目标面板端口。

检查配置并重载 SSH 服务：

sudo sshd -t && (sudo systemctl reload ssh || sudo systemctl reload sshd)

重载前保留当前 SSH 会话。修改后在本地重新运行转发命令即可。
