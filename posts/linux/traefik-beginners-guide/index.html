Traefik 从安装到实战：Docker 反向代理新手教程

从 Docker Engine 与 Compose 安装，到用 Traefik 反代 Docker 网站并自动申请 HTTPS 证书；提供完整目录、配置文件、执行顺序和排错方法。

本文按 Debian/Ubuntu Linux 主机编写。示例域名 whoami.example.com 和邮箱 you@example.com 都是占位值，必须替换成你自己的；不要把占位域名直接当作可用站点。

这次要搭成什么#

浏览器访问 https://whoami.example.com，Traefik 接收 443 请求、自动申请并续期 Let’s Encrypt 证书，再把请求转发给 Docker 网络里的 whoami 测试服务。80 端口只负责跳转到 HTTPS。

浏览器 --HTTPS:443--> Traefik --Docker 内网--> whoami:80
          HTTP:80----> 301/308 跳转到 HTTPS

这篇只走一条完整路径：Traefik 和测试服务都用 Docker Compose 管理，路由放在独立的动态配置文件里。配置不挂载 Docker socket，也不公开 Dashboard，避免把 Docker 管理接口引入反向代理容器。

Traefik 的几个名词：

  • EntryPoint：入口端口，本例 web=:80、websecure=:443。
  • Router：按域名匹配请求，本例匹配 whoami.example.com。
  • Service：真正提供网页的后端，本例为 http://whoami:80。
  • Provider：配置来源，本例由 File Provider 读取 dynamic/ 里的 YAML。
  • Middleware：路由前后处理请求，本例由静态配置把 HTTP 跳转到 HTTPS。

第 1 步：准备主机、域名和网络#

需要一台 Debian 或 Ubuntu 主机，并能通过 sudo 安装软件。公开网站还必须具备：

  1. 一个你控制的域名，例如 whoami.example.com。
  2. DNS 的 A 记录指向这台主机的公网 IPv4。只有确认 IPv6 也能从互联网访问时才添加 AAAA 记录；错误的 AAAA 会让部分访客连错地址。
  3. 云安全组/主机防火墙允许 TCP 80、443；家用路由器还需把公网 TCP 80、443 转发到 Traefik 主机。
  4. 网络允许互联网访问 TCP 80，供 Let’s Encrypt HTTP-01 验证。CGNAT、运营商封入站端口或公司防火墙都可能使这一步失败。

先确认系统和端口占用：

cat /etc/os-release
sudo ss -lntp | grep -E ':(80|443)\b' || true

如果 80/443 已由 Nginx、Apache 或其他程序占用，先确认它们的用途；不要直接停掉未知服务。Traefik 不能同时绑定已被占用的主机端口。

第 2 步：安装 Docker Engine 和 Compose Plugin#

以下命令适用于 Debian/Ubuntu 官方仓库支持的发行版。如果主机已经安装 Docker，请先运行 sudo docker version 和 sudo docker compose version；两条都正常就跳过本节安装命令，不要在生产主机上盲目替换 Docker 软件包。缺少 Docker 时，下面命令会添加 Docker 官方软件源并安装 Engine、CLI、Buildx 和 Compose Plugin。

sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL "https://download.docker.com/linux/$(. /etc/os-release && printf '%s' "$ID")/gpg" -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
printf 'Types: deb\nURIs: https://download.docker.com/linux/%s\nSuites: %s\nComponents: stable\nArchitectures: %s\nSigned-By: /etc/apt/keyrings/docker.asc\n' "$(. /etc/os-release && printf '%s' "$ID")" "$(. /etc/os-release && printf '%s' "$VERSION_CODENAME")" "$(dpkg --print-architecture)" | sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker

检查安装结果：

sudo docker version
sudo docker compose version
sudo docker run --rm hello-world

若 Docker 官方仓库没有你的发行版代号，apt-get update 会明确报错，先按 Docker 官方安装文档核对该系统版本，不要把其他 Debian/Ubuntu 代号盲目写进软件源。本文后续命令统一使用 sudo docker ...；不要为了省略 sudo 就把普通账号加入 docker 组，因为该组成员基本拥有 root 级 Docker 控制能力。

官方安装说明：Docker Engine 安装。

第 3 步：创建工作目录#

本例固定使用 /opt/traefik-demo，Compose 文件、静态配置、动态路由和证书数据都放在这里。命令以当前登录用户创建目录，后续用 sudo docker compose 启动：

sudo install -d -o "$USER" -g "$(id -gn)" -m 0750 /opt/traefik-demo
cd /opt/traefik-demo
mkdir -p dynamic letsencrypt

创建 ACME 存储文件。下列写法仅在文件不存在时创建空文件；重复执行不会清空已经签发的证书数据：

test -e letsencrypt/acme.json || (umask 077 && : > letsencrypt/acme.json)
chmod 600 letsencrypt/acme.json

目录最终如下：

/opt/traefik-demo/
├── compose.yml
├── traefik.yml
├── dynamic/
│   └── whoami.yml
└── letsencrypt/
    └── acme.json

编辑文件统一使用 nano 文件名；粘贴代码块正文，不要把 Markdown 的代码围栏复制进去。保存按 Ctrl+O、Enter，再按 Ctrl+X。

第 4 步：写静态配置 traefik.yml#

静态配置决定监听端口、配置来源和 ACME 证书解析器。先把邮箱换成自己能收信的地址：

cd /opt/traefik-demo
nano traefik.yml

完整内容：

api:
  dashboard: false

entryPoints:
  web:
    address: ":80"
    http:
      redirections:
        entryPoint:
          to: websecure
          scheme: https
          permanent: true
  websecure:
    address: ":443"

providers:
  file:
    directory: /etc/traefik/dynamic
    watch: true

certificatesResolvers:
  le:
    acme:
      email: "you@example.com"
      storage: /letsencrypt/acme.json
      httpChallenge:
        entryPoint: web

log:
  level: INFO

accessLog: {}

将 you@example.com 换成你的邮箱。不要启用 api.insecure，也不要映射 Dashboard 的 8080 端口。本例完全不挂载 Docker socket，因此 Traefik 不能通过 Docker API 自动读取容器 labels；站点路由统一由下面的 File Provider 文件管理。

第 5 步：写 Compose 文件 compose.yml#

nano compose.yml

粘贴完整配置：

services:
  traefik:
    image: traefik:v3.8.0
    container_name: traefik
    restart: unless-stopped
    security_opt:
      - no-new-privileges:true
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./traefik.yml:/etc/traefik/traefik.yml:ro
      - ./dynamic:/etc/traefik/dynamic:ro
      - ./letsencrypt/acme.json:/letsencrypt/acme.json
    networks:
      - proxy

  whoami:
    image: traefik/whoami:v1.11.0
    container_name: whoami
    restart: unless-stopped
    expose:
      - "80"
    networks:
      - proxy

networks:
  proxy:
    name: traefik-demo-proxy

whoami 没有 ports:，所以它的 80 端口不会直接发布到主机或互联网；Traefik 与它在同一个 Docker 网络中，Traefik 可通过服务名 whoami 连接后端。

第 6 步：写动态路由 dynamic/whoami.yml#

nano dynamic/whoami.yml

完整内容：

http:
  routers:
    whoami:
      rule: "Host(`whoami.example.com`)"
      entryPoints:
        - websecure
      service: whoami
      tls:
        certResolver: le

  services:
    whoami:
      loadBalancer:
        servers:
          - url: "http://whoami:80"

把 whoami.example.com 换成你实际准备的域名。这里的两个 whoami 名称分别是 Router 名和 Service 名；service: whoami 把路由连到同名后端配置。后端地址使用 Compose 服务名和容器端口，不是主机公网 IP。

第 7 步：检查配置，再启动#

启动前再次确认域名和邮箱已替换：

cd /opt/traefik-demo
grep -R -nE 'whoami\.example\.com|you@example\.com' traefik.yml dynamic compose.yml

如果 grep 仍有输出，按输出文件逐个编辑替换；确认输出为空后再继续。先解析 Compose 配置并拉取镜像：

sudo docker compose config
sudo docker compose pull

docker compose config 必须成功且没有 YAML/路径错误。现在可以启动：

sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 traefik

若 ACME 还没签发，不要反复删除 acme.json 或连续重建账户；先检查 DNS 和公网 80 端口。Traefik 会在 HTTPS 路由收到请求后申请证书。

第 8 步：验证访问和证书#

从主机查看服务状态和监听端口：

sudo docker compose ps
sudo ss -lntp | grep -E ':(80|443)\b'

先从另一台网络设备，或主机在公网 DNS 已生效后测试：

curl -I http://whoami.example.com/
curl -Iv https://whoami.example.com/

将命令中的域名替换成自己的。预期结果：HTTP 返回 301 或 308 并跳到 https://...；HTTPS 返回 200，证书校验成功，页面内容包含 whoami 返回的请求信息。若是在家里访问公网域名失败但手机流量正常，路由器可能不支持 NAT loopback；可在内网 DNS 配置同一域名指向 Traefik 主机的内网地址。

把自己的 Docker 网站接进来#

每个站点在 dynamic/ 下单独创建一个 YAML 文件，复制 whoami.yml 的结构并替换三处：

  1. rule 里的 Host 改成这个网站的域名。
  2. service 名称改成该网站的 Compose 服务名。
  3. servers[].url 改成同网络可访问的服务名和容器端口，例如 http://my-site:8080。

后端容器必须加入 traefik-demo-proxy 网络。若后端在另一个 Compose 项目里，可在其 Compose 中声明并加入同一个已存在网络：

networks:
  proxy:
    external: true
    name: traefik-demo-proxy

并在后端服务中加入：

services:
  my-site:
    networks:
      - proxy

这两段属于后端项目的 Compose 配置，不能单独当成完整 Compose 文件运行。修改后在 Traefik 目录执行 sudo docker compose logs --tail=100 traefik 查看动态配置错误；File Provider 监视 dynamic/，通常无需重启 Traefik。

后端不在 Docker 网络里怎么办#

若服务运行在另一台机器，先在 Traefik 主机检查它能否访问：

curl -I http://192.0.2.20:8080/

192.0.2.20 是文档示例地址，必须替换为你自己的后端地址。能收到 HTTP 响应后，在对应动态文件中将 Service 改成：

  services:
    my-site:
      loadBalancer:
        servers:
          - url: "http://192.0.2.20:8080"

同时把 Router 的 service: 改为 my-site。主机防火墙只允许 Traefik 主机访问后端端口，不要为了反代把管理端口开放给整个互联网。localhost 指的是 Traefik 容器本身，不是 Docker 主机或另一台服务器。

维护与排错#

改配置后依次运行：

cd /opt/traefik-demo
sudo docker compose config
sudo docker compose ps
sudo docker compose logs --tail=100 traefik

常见现象：

  • Traefik 404：请求已到 Traefik，但没有 Router 匹配。核对浏览器域名与 Host(...) 是否完全一致、Router YAML 是否加载。
  • 502 Bad Gateway：Router 已匹配但后端不可达。核对后端 URL、端口、网络、监听地址；在 Traefik 主机或容器里测试后端。
  • ACME timeout：核对 DNS 公网解析、云安全组、主机防火墙、路由器 80 转发、CGNAT，以及 TCP 80 是否从公网能到主机。
  • ACME unauthorized：A/AAAA 记录可能指向别处，或域名并非你控制的域名；错误 AAAA 记录也要一并检查。
  • 容器启动失败/端口绑定失败：执行 sudo docker compose ps 和 sudo docker compose logs --tail=100 traefik，并检查主机 80/443 是否已有其他服务占用。
  • 改了动态 YAML 没变化：确认文件在 /opt/traefik-demo/dynamic/，扩展名为 .yml，缩进正确，再看 Traefik 日志。

证书和 ACME 账户数据保存在 letsencrypt/acme.json。不要删除它、不要公开它，也不要提交到 Git。升级前备份此文件及 Compose/YAML 配置；然后更新 Compose 中的镜像版本，再运行：

sudo docker compose pull traefik
sudo docker compose up -d traefik
sudo docker compose logs --tail=100 traefik

验证边界#

本文的配置按 Traefik v3.8.0 文档和 Docker Compose 文件结构编写；本次只做了文档配置检查与 Hugo 构建验证，没有在生产主机部署容器，也没有真实申请 Let’s Encrypt 证书。证书签发仍取决于你的真实域名解析、公网路由和防火墙条件。
