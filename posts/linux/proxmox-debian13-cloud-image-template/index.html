在 PVE 上用 Debian 13 官方 Cloud Image 创建模板

按顺序在 Proxmox VE 上检查 VMID、网桥与存储，安装脚本依赖，下载并校验 Debian 13 官方 Cloud Image，创建 Cloud-Init 模板并克隆配置。

本文只讲 Debian 13 官方 Cloud Image 模板的准备、创建和克隆。命令均在 PVE 节点 Shell 以 root 执行，不是在你的电脑或虚拟机里执行。示例 VMID、存储名、网桥和 IP 都要先按本机情况核对；标为文档示例的 IP 不可直接使用。

先准备：确认节点、VMID、存储和网桥

在 PVE 网页选择目标节点 → Shell，先运行只读检查：

pveversion -v
id -u
qm list
pct list
pvesm status
cat /etc/pve/storage.cfg
ip -br link
qm help set
  • id -u 必须输出 0，否则当前不是 root Shell，先切换到 PVE 管理员 Shell。
  • 选择一个同时未被 VM 和 LXC 使用的模板 VMID、一个未使用的克隆 VMID；下文用 923 和 102 举例。
  • qm help set 会显示本机支持的参数；在磁盘参数说明里确认支持脚本使用的 import-from。若没有该参数，不要运行脚本，先升级到支持该语法的 PVE 版本或改用匹配本机版本的导入流程。
  • pvesm status 用于确认存储 ID 和状态；再在 PVE 网页 Datacenter → Storage 或 /etc/pve/storage.cfg 确认所选存储启用了 Disk image 内容类型。示例用 local-lvm；若没有该存储，换成实际支持虚拟机磁盘的存储 ID。
  • 从 PVE 网页 节点 → System → Network 确认网桥名称。示例用 vmbr0；没有这个网桥就替换成实际网桥。
  • 固定 IP 必须属于虚拟机所在网段、未被占用；网关和 DNS 应使用该网段真实可达的地址。示例地址使用 RFC 5737 文档保留网段，仅用于说明格式。
参数文档示例你需要确认
模板 VMID / 克隆 VMID923 / 102两个 ID 都未被 VM 或 LXC 占用
PVE 存储 / 网桥local-lvm / vmbr0存储支持 Disk image；网桥存在
新 VM 名称debian-cloud可自行更改
固定 IPv4 / 网关192.0.2.10/24 / 192.0.2.1文档保留地址，执行前必须换成自己的网络参数

⚠️ 192.0.2.0/24 是文档示例网段，不是可用的家庭/公司网段。切勿把示例 IP 原样配置到 VM。

1. 安装依赖

模板脚本使用 virt-customize 修改磁盘镜像。先安装 libguestfs-tools：

apt-get update
apt-get -s install curl libguestfs-tools

先看模拟安装输出，确认不会移除你需要的 PVE 软件包；确认后再安装：

apt-get install -y curl libguestfs-tools
command -v bash curl sha512sum virt-customize qm

每项都应输出程序路径。若模拟结果要移除 PVE 核心组件，停止操作，不要继续安装。

2. 下载项目中的模板脚本

请在 PVE Shell 下载项目里固定版本的脚本与网络配置，避免 main 分支更新后教程与脚本不一致。本文固定到提交 e9068ee2c74c5975208385364127510d93f69917：

mkdir -p /opt/singbox-ui-debian13/scripts /opt/singbox-ui-debian13/templates

curl -4 -fL --retry 3 --retry-all-errors \
  https://raw.githubusercontent.com/hanigege/singbox-ui-debian13/e9068ee2c74c5975208385364127510d93f69917/scripts/pve-create-template.sh \
  -o /opt/singbox-ui-debian13/scripts/pve-create-template.sh

curl -4 -fL --retry 3 --retry-all-errors \
  https://raw.githubusercontent.com/hanigege/singbox-ui-debian13/e9068ee2c74c5975208385364127510d93f69917/templates/cloud-init-networkd.cfg \
  -o /opt/singbox-ui-debian13/templates/cloud-init-networkd.cfg

chmod 0755 /opt/singbox-ui-debian13/scripts/pve-create-template.sh
bash -n /opt/singbox-ui-debian13/scripts/pve-create-template.sh
test -x /opt/singbox-ui-debian13/scripts/pve-create-template.sh && echo '脚本可执行'
ls -l /opt/singbox-ui-debian13/templates/cloud-init-networkd.cfg

bash -n 无输出且退出码为 0 表示脚本语法检查通过。网络配置文件让 Cloud-Init 使用 Debian 的 systemd-networkd renderer。下载源代码使用 curl -4，用于绕开某些网络的 IPv6 连接问题。

3. 创建 Debian 13 模板

运行脚本前再次确认 923 没被 VM/LXC 使用，并确认 /tmp 与选定存储有足够空间。脚本会拒绝覆盖已有 VMID；若之前中途失败，先检查 qm list 和 qm config 923，不要盲目删除已有 VM。

TEMPLATE_ID=923 STORAGE=local-lvm BRIDGE=vmbr0 \
  bash /opt/singbox-ui-debian13/scripts/pve-create-template.sh

把 STORAGE、BRIDGE 换成上一步查到的真实值。若你的网络需要自定义 DNS，可在同一条命令前加 DNS_SERVER= 环境变量并填入可达的 DNS 地址；不要照抄文档保留地址。脚本会从 Debian 官方 Cloud Image 目录 下载 debian-13-generic-amd64.qcow2 及同目录的 SHA512SUMS，先校验 SHA-512，再安装 QEMU Guest Agent、清理 machine-id 与 SSH host key、导入磁盘、扩展到 8 GiB，最后转换成模板。校验失败时脚本会停止，不要跳过校验继续做。

脚本显示完成后检查模板配置：

qm list
qm config 923

确认存在系统磁盘、Cloud-Init 磁盘、agent: 1 和正确的网桥；模板应为停止状态。模板不包含虚拟机密码或 SSH 私钥。

4. 克隆并配置虚拟机

先从模板创建完整克隆：

qm clone 923 102 --full 1 --storage local-lvm --name debian-cloud

如果前面选的存储不是 local-lvm，此处也要换成同一个实际存储 ID。

下面的 IP 是 RFC 5737 文档示例地址，不能直接用于真实网络。先把两行改成你 LAN 中未被占用的 VM 地址和网关，再运行：

VM_IP='192.0.2.10/24'
GATEWAY='192.0.2.1'

qm set 102 \
  --cores 2 \
  --memory 1024 \
  --agent enabled=1 \
  --ciuser vmuser \
  --ipconfig0 "ip=${VM_IP},gw=${GATEWAY}"

接着在 PVE 网页打开 VM 102 → Cloud-Init：

  1. 确认用户是 vmuser；按需要在网页设置密码，不要把密码写进命令行或文章。
  2. 在 SSH public key 栏粘贴你自己的 SSH 公钥（不是私钥）。
  3. 将 DNS Nameserver 改成该 VM 网络实际可达的 DNS 地址。
  4. 点击 Regenerate Image，再回到 PVE Shell 刷新 Cloud-Init 配置：
qm cloudinit update 102
qm config 102

确认 ipconfig0、ciuser、ide2 Cloud-Init 磁盘和 agent: 1 都符合预期。模板原有的 Cloud-Init DNS 若不适合你的网络，应在此处改掉。

5. 启动和确认

qm start 102
qm status 102
qm agent 102 ping
qm agent 102 network-get-interfaces

首次启动时 Cloud-Init 会生成用户、SSH key、网络和机器身份；等 1–2 分钟再查 Guest Agent。qm agent ... 刚启动就失败时先等一会儿并查看 PVE 任务日志，不要立刻删除或重建 VM。成功后应能看到 guest agent 响应和网卡地址；再从你的电脑用 ssh vmuser@<实际虚拟机IP> 验证密钥登录。

常见问题

  • 找不到 virt-customize： 返回第 1 步安装 libguestfs-tools，检查安装时没有报错。
  • 下载 GitHub 文件超时： 检查 PVE 节点 DNS、网关和出站网络；命令中的 curl -4 可绕开部分 IPv6 问题。
  • SHA-512 校验失败： 脚本会停止；不要改成跳过校验。检查网络和磁盘空间后重新下载。
  • qm set 报 storage/content 不支持： 检查所选存储在 Datacenter → Storage 启用了 Disk image，且状态为 active。
  • Cloud-Init 后 IP 没更新： 核对 Cloud-Init 页面里的地址、掩码、网关和 DNS；点击 Regenerate Image，执行 qm cloudinit update 102，再重启 VM。
  • Guest Agent 暂时不响应： 等首次启动和 Cloud-Init 完成；确认 VM 已启动且 Cloud-Init 磁盘存在，再查看 PVE 任务日志。

完成标准

  • qm config 923 显示 template: 1；qm status 102 显示克隆 VM 正在运行。
  • qm config 102 中能看到 Cloud-Init 磁盘、agent: 1、正确网桥和你自己的 IP 配置。
  • qm agent 102 ping 成功，并且从你的电脑可以用已配置的 SSH 密钥登录 vmuser。

验证范围与限制

本文脚本已用 bash -n 做语法检查，并在隔离沙箱中以模拟的 curl、virt-customize 和 qm 命令检查了执行顺序与参数；没有连接或修改真实 PVE 节点，也没有实际启动 Debian 虚拟机。因此，存储兼容、Cloud-Init 首次启动和 Guest Agent 的最终效果，必须在你的 PVE 上按上面的检查项实测；沙箱模拟不等于真实 PVE 验证。
