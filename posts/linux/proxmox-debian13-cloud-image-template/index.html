在 PVE 上用 Debian 13 官方 Cloud Image 创建模板

从 Debian 官方 Cloud Image 下载与校验开始，在 Proxmox VE 中导入磁盘、添加 Cloud-Init 并创建模板，再克隆出可登录的 Debian 13 虚拟机。

本文讲一条通用流程：下载 Debian 官方 Cloud Image → 导入 PVE → 添加 Cloud-Init → 转成模板 → 克隆并首次登录。不依赖任何个人脚本或项目仓库。 命令都在 PVE 网页的节点 Shell 中以 root 执行；克隆后的 Debian 命令才在虚拟机里执行。

先认识这几个名词

  • Cloud Image：Debian 已经装好系统的虚拟磁盘，不需要再从 ISO 安装。
  • Cloud-Init：第一次开机时，按 PVE 里填写的用户名、SSH 公钥和网络配置初始化系统。
  • 模板：关机后转成只读母盘，之后从它克隆出一台台独立虚拟机。

1. 检查 PVE 的存储、网桥和 VMID

在 PVE 网页左侧选中目标节点，点 Shell。先确认自己在 PVE 节点 Shell，而不是浏览器里打开的 Debian 虚拟机终端：

pveversion
qm list
pct list
pvesm status
ip -br link

记录三项信息，后面按你的环境替换：

  • STORAGE：存虚拟机磁盘的存储 ID。常见是 local-lvm 或 local；以 pvesm status 和 PVE 网页 Datacenter → Storage 为准，并确认该存储允许 Disk image。
  • BRIDGE：虚拟机网卡连接的 Linux Bridge。常见是 vmbr0；以 节点 → System → Network 中实际存在的网桥为准。
  • TEMPLATE_ID：模板 VMID。例子用 9000，必须在整个 PVE 集群中未被 VM 或容器使用；克隆 VMID 也要另选一个未使用的数字。

下面的命令用 local-lvm、vmbr0 和 9000 作示例。你的存储或网桥名称不同，就把相应值换成刚查到的值；不要因为示例常见就假定本机一定有它们。

2. 下载并校验 Debian 13 官方镜像

这里使用 Debian Cloud Team 发布的 generic amd64 镜像。generic 使用 Debian 标准内核，适用范围比 genericcloud 更广；若你的 PVE 是 ARM 主机，应改用官方目录里的 arm64 镜像，不能下载 amd64 文件。

镜像约 440 MB，下载目录需要有至少 1 GB 可用空间。以下示例存到 PVE 的 /root/cloud-images：

set -euo pipefail

IMAGE='debian-13-generic-amd64.qcow2'
IMAGE_DIR='/root/cloud-images'
IMAGE_BASE='https://cloud.debian.org/images/cloud/trixie/latest'

mkdir -p "$IMAGE_DIR"
df -h "$IMAGE_DIR"
cd "$IMAGE_DIR"

curl -fLO "$IMAGE_BASE/$IMAGE"
curl -fLO "$IMAGE_BASE/SHA512SUMS"

grep -E "^[[:xdigit:]]{128}  ${IMAGE}$" SHA512SUMS | sha512sum -c -

最后应显示 debian-13-generic-amd64.qcow2: OK。校验失败就停止，不要导入未校验的镜像。官方 latest 目录会更新，所以每次下载都要同时取当时目录里的 SHA512SUMS，不要复制旧教程里的固定哈希。

3. 创建空 VM 并导入镜像

先设置本文示例值，再创建一台尚未安装系统的空 VM。这里不启动它：

TEMPLATE_ID=9000
STORAGE='local-lvm'
BRIDGE='vmbr0'
IMAGE_DIR='/root/cloud-images'
IMAGE='debian-13-generic-amd64.qcow2'

qm create "$TEMPLATE_ID" \
  --name debian-13-cloud-template \
  --memory 2048 \
  --cores 2 \
  --net0 "virtio,bridge=$BRIDGE"

qm importdisk "$TEMPLATE_ID" "$IMAGE_DIR/$IMAGE" "$STORAGE"
qm config "$TEMPLATE_ID"

在 qm config 输出中找到 unused0:，例如：

unused0: local-lvm:vm-9000-disk-0

把你自己输出里 unused0: 后面的完整磁盘 ID复制下来，赋给 DISK_VOLID。如果你用的是 local 或其它存储，磁盘 ID 格式可能不同，不能照抄上面的例子：

DISK_VOLID='local-lvm:vm-9000-disk-0'

qm set "$TEMPLATE_ID" \
  --scsihw virtio-scsi-pci \
  --scsi0 "$DISK_VOLID" \
  --ide2 "$STORAGE:cloudinit" \
  --boot order=scsi0 \
  --serial0 socket \
  --vga serial0

这一步把导入的系统盘接到 SCSI 控制器、增加 Cloud-Init 配置盘，并设置从系统盘启动。若 qm set 报存储不支持，先检查所选存储是否支持虚拟机磁盘镜像，不要换成不存在的磁盘 ID继续执行。

4. 检查并转换成模板

qm config "$TEMPLATE_ID"
qm status "$TEMPLATE_ID"

确认配置中有 scsi0 系统盘、ide2 Cloud-Init 盘、正确的网桥，且 VM 处于停止状态。检查无误后转换为模板：

qm template "$TEMPLATE_ID"
qm config "$TEMPLATE_ID" | grep '^template:'

预期看到 template: 1。到这里模板已经做好，不要启动模板本身；下面要克隆一台测试虚拟机。

5. 克隆虚拟机并填写首次启动信息

使用完整克隆，初学时更容易理解：克隆出来的磁盘是独立副本，不依赖模板磁盘的运行状态。把 CLONE_ID 换成未使用的 VMID：

TEMPLATE_ID=9000
CLONE_ID=101

qm clone "$TEMPLATE_ID" "$CLONE_ID" \
  --full 1 \
  --name debian13-test

然后在 PVE 网页选择新 VM 101 → Cloud-Init，填写：

  1. User：debian。
  2. SSH public key：粘贴你自己电脑上的公钥，例如 id_ed25519.pub 的内容。不要粘贴私钥，也不要把私钥上传到 PVE。
  3. IP Config：有 DHCP 的网络选 DHCP；没有 DHCP 时，填写你自己网段中未占用的 IP、前缀长度和网关。
  4. DNS：填写该 VM 所在网络可访问的 DNS 地址。
  5. 点击 Regenerate Image，再启动 VM：
qm cloudinit update "$CLONE_ID"
qm start "$CLONE_ID"
qm status "$CLONE_ID"

Cloud Image 默认没有可直接使用的密码登录方式。首次启动时 Cloud-Init 会创建 debian 用户并安装你提供的公钥；不要尝试使用网上流传的默认密码。

6. 登录并验收

等待虚拟机启动和 Cloud-Init 完成。在 PVE VM 的 Summary 页面查看 IP，然后从你自己的电脑用对应私钥登录：

VM_IP='替换成 PVE 显示的实际 VM IP'
ssh "debian@$VM_IP"

先把 VM_IP 赋值右侧的说明文字换成 PVE 中看到的真实 IP，再运行 SSH 命令。登录后检查：

cloud-init status --wait
ip -br address

cloud-init status --wait 最终应显示 status: done，网卡应获得你在 Cloud-Init 页面配置的地址。能用 SSH 公钥登录，就表示从镜像导入、Cloud-Init 到模板克隆这条流程已经打通。

可选：安装 QEMU Guest Agent

Debian 通用 Cloud Image 不预装 qemu-guest-agent。如果希望 PVE 显示更完整的来宾信息或执行 Guest Agent 操作，先在已登录的克隆 VM 里安装并启动它：

sudo apt update
sudo apt install -y qemu-guest-agent
sudo systemctl enable --now qemu-guest-agent

然后在 PVE 节点 Shell 启用对应 VM 的 Guest Agent：

qm set "$CLONE_ID" --agent enabled=1

这是可选项，不影响 Cloud-Init 模板和 SSH 登录的基本流程。

常见问题

  • VM <id> already exists：模板或克隆 VMID 已被占用，换一个空闲编号；不要删除不认识的 VM 来腾位置。
  • storage does not support content-type images：所选存储没有启用磁盘镜像内容，去 Datacenter → Storage 检查；不要把 ISO 存储 ID 当作虚拟机磁盘存储。
  • 导入后看见 unused0，但不知道怎么接盘：将 qm config 中 unused0: 后面的整段值原样填到 DISK_VOLID，不要只复制末尾文件名。
  • Cloud-Init 页面没有公钥或 IP 设置：检查 VM 是否已有 ide2 Cloud-Init 磁盘；填写后先点 Regenerate Image 再启动。
  • SSH 超时：检查 VM 是否拿到 IP、PVE 网桥是否连接到正确网络，以及你的电脑能否路由到该 IP。
  • SSH 提示认证失败：Cloud Image 没有通用默认密码；核对 Cloud-Init 用户是 debian，公钥粘贴正确，并在首次启动前重新生成 Cloud-Init 配置。

验证边界

本文按 Proxmox VE 的 qm importdisk、Cloud-Init 磁盘、模板和克隆流程编写，并核对了 Debian 13 官方镜像目录与校验文件。没有在真实 PVE 节点导入镜像或启动 VM，所以具体存储 ID、网桥、Cloud-Init 首次启动和 SSH 连通性，仍需在你的 PVE 环境按验收步骤确认。
