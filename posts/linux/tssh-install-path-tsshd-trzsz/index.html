tssh 指定安装路径：trzsz / tsshd 装给普通用户还是 /usr/local/bin（Alpine 实测）

tssh --install-path 专题：方案一只装给普通用户（~/.local/bin，无需 root，含单引号坑）、方案二装进 /usr/local/bin（tssh 不支持 sudo，实测两段式 doas mv 才可行）、Alpine 报错排查（静态二进制不需要 gcompat），附 tsshd UDP 全部配置项、trz/tsz 传文件 -t 0、enc-secret 等常用参数

💡 一句话结论：tssh --install-path 改的是服务器上的安装目录，不是本地目录。只想「给自己这个普通用户用、不碰 root」，就写 --install-path '~/.local/bin'（单引号不能省）；想把 trz / tsz / tsshd 放进 /usr/local/bin，tssh 本身没有 sudo 能力，正确姿势是「先装到用户目录 → 再 doas mv」。

本文覆盖三件事：方案一（普通用户安装，无需 root）、方案二（全系统 /usr/local/bin，含实测可行做法）、Alpine 排错（什么时候才真需要 gcompat）。顺带把 tsshd 的 UDP 模式、trz/tsz 传文件、密码加密、DNS SRV 这些常用参数一次说清。所有命令都在一台真实的 Alpine 3.23.4 服务器上跑过，末尾有「实战验证记录」可对查。

先把参数分清楚

真实 tssh --help（v0.1.26）里跟安装有关的部分：

  --install-trzsz        [tools] install trzsz to the remote server
  --install-tsshd        [tools] install tsshd to the remote server
  --install-path path    [tools] install path, default: '~/.local/bin/'
  --trzsz-version x.x.x  [tools] install the specified version of trzsz
  --trzsz-bin-path path  [tools] trzsz binary installation package path
  --tsshd-version x.x.x  [tools] install the specified version of tsshd
  --tsshd-bin-path path  [tools] tsshd binary installation package path

三个必须先搞对的点：

  1. 这些参数是给 tssh 客户端用的，装的是远端服务器上的程序。
  2. --install-path 的默认值已经是 ~/.local/bin/（远端登录用户的家目录），所以「不指定路径」就等于方案一。
  3. 每条命令末尾必须跟目标主机——~/.ssh/config 里的别名，或 user@ip。

漏了主机会怎样？非交互执行（脚本、CI）时直接报错：

destination is required when running tssh in non-interactive mode

交互式终端里则会弹出服务器列表让你选。脚本里漏主机 = 直接失败。

方案一：只装给普通用户（推荐，无需 root）

前置条件：

  • 本机已装好 tssh（tssh --version 有输出）；
  • ~/.ssh/config 里有这台服务器的别名。本文用 us685 代指，你换成自己的别名。

第 1 步：一条命令装完（重点看单引号）

tssh --install-path '~/.local/bin' --install-trzsz us685
tssh --install-path '~/.local/bin' --install-tsshd us685

实测输出：

[InstallTrzsz] trzsz 1.2.0 installation to /home/jay/.local/bin completed successfully

[InstallTsshd] tsshd 0.1.10 installation to /home/jay/.local/bin completed successfully
[InstallTsshd] you may need to specify 'TsshdPath /home/jay/.local/bin' in ~/.ssh/config

✅ 判断成功的唯一标准：出现 completed successfully。过程里那些 download percentage 100% / upload percentage 100% 只是进度条，不代表装好了。

不需要提前 mkdir。 tssh 自己会在远端执行 mkdir -p -m 755 <路径>（源码 tools_install.go 的 mkdirInstallPath），目录不存在它自己建。

重复执行也安全：同版本已装时只提示一句，不会重复下载：

[InstallTrzsz] trzsz 1.2.0 has been installed in /home/jay/.local/bin

⚠️ 最容易抄错的地方：~ 外面的单引号不能省。

不加引号时，是你本机的 shell 先把 ~ 展开成本机家目录，再把绝对路径发给服务器。实测（本机用户是 hermesuser）：

[InstallTsshd] mkdir [/home/hermesuser/.local/bin] failed: mkdir: can't create directory '/home/hermesuser/': Permission denied

服务器上根本没有 /home/hermesuser 这个目录，于是失败。加单引号后 ~ 原样传给远端，tssh 再解析成远端用户的 HOME（实测解析结果 /home/jay/.local/bin）。

官方文档原话：「若 --install-path 安装目录包含 ~/，则必须加上单引号，如 --install-path '~/path'」。

第 2 步：把远端的 ~/.local/bin 加进 PATH

Alpine / Debian 默认的 PATH 里没有 ~/.local/bin：

PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

于是「装好了但找不到命令」。tssh 装完其实会提醒你（实测：先把 /usr/bin/trz 移走再重装，就能看到这句）：

[InstallTrzsz] you may need to add /home/jay/.local/bin to the PATH environment variable

在服务器上执行（不是本机）：

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.profile

重新登录后验证：

ssh us685 'echo $PATH; command -v trz tsz'

💡 为什么写 ~/.profile 而不是 ~/.bashrc：tssh 检查远端有没有装好，用的是 $SHELL -l -c 'trz -v'（登录 shell）。登录 shell 读 ~/.profile（Alpine 的 /bin/sh、bash 都是），不读 ~/.bashrc。写错文件 = 明明装了 tssh 还提示找不到。

第 3 步：tsshd 要额外告诉 tssh 路径（只有 UDP 模式需要）

方案一装完 tsshd 后，实测提示：

[InstallTsshd] you may need to specify 'TsshdPath /home/jay/.local/bin' in ~/.ssh/config

在本机 ~/.ssh/config 对应 Host 段里加一行：

Host us685
    HostName 203.0.113.10
    User jay
    #!! TsshdPath /home/jay/.local/bin/tsshd

💡 #!! 是 tssh 的扩展前缀：标准 ssh 当注释忽略，tssh 当有效配置。同一份 ~/.ssh/config 两边都能用。

走方案二装进 /usr/local/bin（本来就在 PATH 里）时，这行可以省略——tssh 会在 PATH 里找 tsshd。

第 4 步：验证

tssh us685 '~/.local/bin/trz -v; ~/.local/bin/tsshd -v'

实测：

trz (trzsz) go 1.2.0
trzsz sshd 0.1.10

方案二：装到 /usr/local/bin（全系统可用，需要 root）

先纠正一个常见误解：前面加 doas tssh 并不管用

很多人以为「本机加 doas/sudo 就能装系统级」。实际链路是：

  • doas / sudo 提升的是本机这个 tssh 进程的权限；
  • 真正写文件的是 tssh 通过 SSH 在服务器上以登录用户身份执行的 mkdir 和 scp。

所以只要 SSH 登录的是普通用户 jay，写 /usr/local/bin 必然失败。实测（普通用户直接指定系统目录）：

[InstallTrzsz] upload trzsz binary files failed: scp response [1]: scp: /usr/local/bin/.trz.tmp.18e174fb079605a3: Permission denied

⚠️ 这个报错很有迷惑性：前面 download percentage 100% 已经走完了，看着像成功。判据只看 completed successfully。

实测可行的做法：两段式

第 1 步，先用方案一装到用户可写的临时目录：

tssh --install-path '~/tmp-install' --install-trzsz us685
tssh --install-path '~/tmp-install' --install-tsshd us685

第 2 步，登录服务器，用 doas/sudo 挪进 /usr/local/bin：

ssh us685
doas mv ~/tmp-install/trz ~/tmp-install/tsz ~/tmp-install/tsshd /usr/local/bin/
rmdir ~/tmp-install

Alpine 用 doas，Debian/Ubuntu 用 sudo。jay 在 wheel 组且 doas 免密时可省密码（实测 doas -n true 返回 0）。

第 3 步，验证（/usr/local/bin 默认就在 PATH 里，不用改 PATH、不用配 TsshdPath）：

ssh us685 'command -v trz tsz tsshd; trz -v; tsshd -v'

实测：

/usr/local/bin/trz
/usr/local/bin/tsshd
trz (trzsz) go 1.2.0
trzsz sshd 0.1.10

什么时候才值得用方案二

  • 服务器上有多个用户都要用 trz/tsz；
  • 要以别的用户身份跑 UDP 会话（systemd 服务、定时脚本）；
  • 不想给每个账号都维护 PATH 和 TsshdPath。

只有一个用户、只自己用 → 方案一更干净，不给系统添垃圾。

两种方案对比

方案一 ~/.local/bin方案二 /usr/local/bin
需要 root / doas不需要需要，且得两步
PATH 处理手动加进 ~/.profile默认已包含
tsshd 额外配置必须配 #!! TsshdPath不需要
影响范围当前用户全机
升级方式重跑同一条命令重跑 + 再 mv 一次
适合场景自己用（推荐）多用户 / 常驻服务

Alpine 排错：什么时候才真需要 gcompat

结论：tssh / trzsz / tsshd 的官方 Linux 二进制是 Go 静态链接，Alpine 直接能跑，不需要 gcompat。

实测（Alpine 3.23.4 aarch64/x86_64，未安装 gcompat/libc6-compat）：

$ file /tmp/tssh_test
/tmp/tssh_test: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), statically linked, ... stripped

$ ldd /tmp/tssh_test
/lib/ld-musl-x86_64.so.1: /tmp/tssh_test: Not a valid dynamic program

$ /tmp/tssh_test --version
trzsz ssh 0.1.26

ldd 那句 Not a valid dynamic program 是静态程序的正常现象，不是错误，别被它带偏。

那 apk add gcompat libc6-compat 什么时候有用？——跑glibc 动态链接的程序时。三种「not found」要对症下药：

报错原文真正原因解法
sh: ./xxx: not found（文件明明存在）缺 glibc 动态加载器（glibc 程序跑在 musl 上）doas apk add gcompat libc6-compat
cannot execute binary file: Exec format error架构不对（x86_64 包放到 aarch64 机器）下对应架构的包
sh: ./xxx: Permission denied没有执行权限chmod +x xxx

诊断顺序：先 file xxx 看是 statically 还是 dynamically linked，再 ldd xxx。别一上来就装兼容层。

另外，Alpine 的 apk 源里没有这些包，别白试（实测）：

$ apk add --simulate tssh
ERROR: unable to select packages:
  tssh (no such package):
    required by: world[tssh]

只能用官方 GitHub Releases 的静态包 + 上面两种安装方案。

UDP 模式（tsshd）：弱网、切网、休眠都不掉线

原理：tssh 先作为普通 ssh 客户端登录服务器，在服务器上起一个 tsshd 进程；tsshd 在 61001–61999 里挑一个空闲 UDP 端口（默认值来自 tsshd 源码 kDefaultPortRange = "61001-61999"），把端口经 ssh 通道回传给 tssh；然后原来的 ssh 连接被关闭，tssh 改走 UDP 与 tsshd 通信。所以断网、换 Wi-Fi、合盖休眠之后能原地接上（类似 mosh）。

前提：服务器上装了 tsshd；方案一装的记得配 TsshdPath。

最简用法：

tssh --udp us685      # UDP + QUIC（默认协议）
tssh --kcp us685      # UDP + KCP（对延迟更敏感）
tssh --tcp us685      # 强制退回普通 TCP（UDP 被封时用）

写进本机 ~/.ssh/config 一劳永逸：

Host us685
    HostName 203.0.113.10
    User jay
    #!! UdpMode Yes
    #!! TsshdPort 61001-61999
    #!! TsshdPath /home/jay/.local/bin/tsshd
    #!! UdpAliveTimeout 86400
    #!! UdpHeartbeatTimeout 3
    #!! UdpReconnectTimeout 15
    #!! ShowNotificationOnTop yes
    #!! ShowFullNotifications yes
    #!! UdpProxyMode UDP

参数含义（默认值已对照 tssh / tsshd 源码核实）：

配置取值默认说明
UdpModeNo / Yes / QUIC / KCPNoYes 即 QUIC；KCP 延迟更低但耗流量
TsshdPort端口范围或离散列表61001-61999支持 6022,7022、8010-8020,9020 这类写法
TsshdPath远端 tsshd 绝对路径无（走 PATH）方案一必须配
UdpAliveTimeout秒86400（10 天）断开超过此时长，两端都退出，不再支持重连
UdpHeartbeatTimeout秒3超过则尝试换路重连
UdpReconnectTimeout秒15超过则弹出「失去连接」通知
ShowNotificationOnTopyes / noyes通知显示在屏幕顶部（会盖住部分输出）
ShowFullNotificationsyes / noyesno 只输出一行
UdpProxyModeUDP / TCPUDP防火墙禁 UDP 时改 TCP 兜底，延迟会变大

⚠️ 实测注意：UDP 模式是给交互式登录用的。同一条命令走 TCP 正常：

$ tssh us685 'hostname > /tmp/exec_tcp.txt'   → 文件生成，内容 localhost
$ tssh --udp us685 'hostname > /tmp/exec_udp.txt'  → 文件没生成

要跑一次性命令/脚本就用普通 TCP；UDP 模式用来长期挂着交互会话（实测 pty 交互登录下 hostname 正常返回）。

传文件：trz / tsz 与那个必须知道的 -t

服务器上装好 trzsz 后，直接在远端 shell 里用（tmux 里也能用，这是 trzsz 相对 lrzsz 的最大优势）：

  • 收文件：远端执行 trz，然后从本机把文件拖进 tssh 窗口（tssh 支持拖拽上传）。也可用 tssh --upload-file <本地路径> us685 直接推。
  • 发文件：远端执行 tsz 文件名，文件落到本机下载目录（可用 --download-path 指定）。

大文件、慢线路最常撞的坑是超时。默认每个数据块 20 秒超时，实测 trz -h：

  -t N, --timeout N      timeout ( N seconds ) for each buffer chunk.
                         N <= 0 means never timeout. (default: 20)

所以长传时加 -t 0 永不超时：

trz -t 0
tsz -t 0 大文件.tar.gz

其他几个实用功能

密码 / 答案加密（encPassword）

tssh --enc-secret

输入密码或答案 → 得到密文（同一密码每次结果不同，正常）。配置里写成：

Host server2
    #!! encPassword de88c4dbdc95d85303682734e2397c4d8dd29bfff09ec53580f31dd40291fc8c7755
    #!! encQuestionAnswer1 93956f6e7e9f2aef3af7d6a61f7046dddf14aa4bbd9845dbb836fe3782b62ac0d89f

密码里含 #、空格等特殊字符时，直接写明文常导致登录失败，一律用密文。

命令行加站点（--new-host）

tssh --new-host

TUI 里依次填 ConfigPath（回车用默认）/ HostAlias / HostName / Port / UserName / Password，完成后可立即登录。

终端标题

不用 tssh 也能做——在服务器的 ~/.bashrc 里：

# 固定标题
PROMPT_COMMAND='echo -ne "\033]0;我的服务器\007"'

# 随环境变量变化
PROMPT_COMMAND='echo -ne "\033]0;${USER}@${HOSTNAME}: ${PWD}\007"'

反过来，在本机 ~/.tssh.conf（或 $XDG_CONFIG_HOME/tssh/tssh.conf）里设 SetTerminalTitle = Yes，tssh 登录后自动设标题。注意两点：服务器的 PROMPT_COMMAND 会覆盖 tssh 设的标题；tssh 退出后不会恢复原标题。

DNS SRV（一个公网 IP 挂多台内网主机）

$ dig +short _ssh._tcp.myhost.mydomain.com SRV
1 1 22029 gateway.mydomain.com.
Host xxx
    #!! DnsSrvName myhost.mydomain.com

后台运行 + 自动重连

tssh -f --reconnect us685

-f 让 tssh 后台运行（隐含 -n），--reconnect 在进程因断线退出时自动重连。

取版本号 / 下载失败时手动指定

# 自己指定版本
tssh --install-path '~/.local/bin' --install-trzsz --trzsz-version 1.2.0 us685

# 自己下好安装包，让 tssh 用本地包
tssh --install-path '~/.local/bin' --install-trzsz \
  --trzsz-bin-path /path/to/trzsz_1.2.0_linux_x86_64.tar.gz us685

tsshd 对应 --tsshd-version / --tsshd-bin-path。

两个硬限制

  • --install-trzsz / --install-tsshd 不支持 Windows 服务器；
  • 不支持跳板机（除非用 ProxyJump 直接跳过去）。
