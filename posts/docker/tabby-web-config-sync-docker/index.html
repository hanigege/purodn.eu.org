Tabby 配置同步自建教程：Docker 部署 tabby-web 全流程（含实测踩坑）

从域名解析到 Caddy 自动 HTTPS，手把手用 Docker 部署 tabby-web 自建 Tabby 配置同步服务，并用 GitHub 账号登录。含实测发现的两个坑：版本包会多套一层目录、桌面端 Sync host 不能带 /api。

家里电脑、公司电脑、笔记本各装了一份 Tabby 终端，连接（Profile）、主题、快捷键改了这台忘了那台——Tabby 自带的配置同步功能可以解决这个问题，但它需要一台同步服务器。官方只提供网页版 demo，不给你托管数据。

这篇教程带你在自己的服务器上部署一套完整的同步服务：Docker 跑 tabby-web + Caddy 自动 HTTPS + GitHub 账号登录，装完之后三台机器的配置自动保持一致，数据完全握在自己手里。

💡 本文不是翻译官方文档：文中所有命令都在一台 Linux 测试机上从头跑过一遍（2026-10-24，镜像 ghcr.io/eugeny/tabby-web:latest，构建时间 2026-10-23）。实测发现两个官方文档没写、照着抄会卡住的坑，分别在第 7 节和第 9 节，都用 ⚠️ 标出来了。

一、你需要准备什么

东西说明大概花费
一台云服务器有公网 IP 的 Linux（Ubuntu / Debian 均可），1 核 1G 就够约 ¥30–50/月
一个域名如 example.com，境外服务器免备案约 ¥50/年
一个 GitHub 账号用来登录，同时创建 OAuth 应用免费
Tabby 终端电脑上已装 tabby.sh 客户端免费

最终效果：浏览器打开 https://tabby.你的域名.com 是一个网页版 Tabby；桌面客户端填上地址和令牌，配置自动云同步。

二、域名解析（先把路修好）

到域名服务商（阿里云 / 腾讯云 / Cloudflare 等）添加一条 DNS 记录：

  • 记录类型：A
  • 主机记录：tabby（即 tabby.example.com）
  • 记录值：你服务器的公网 IP

保存后等几分钟生效。验证：

ping tabby.example.com

解析出的 IP 是你服务器的 IP 即可。

⚠️ 注意：服务器在国内的话，域名必须备案，否则 80 / 443 会被拦截，Caddy 申请不到证书。

三、服务器上安装 Docker

SSH 登录服务器（下文按 root 用户书写）：

ssh root@你的服务器IP

一键安装 Docker 和 Compose 插件：

curl -fsSL https://get.docker.com | sh

验证（两个命令都有版本号输出即成功）：

docker --version
docker compose version

💡 提示：国内服务器拉镜像慢的话，先配镜像加速再继续：

mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://docker.1ms.run"] }
EOF
systemctl restart docker

四、创建 GitHub OAuth 应用（登录用的钥匙）

tabby-web 用 GitHub 账号登录，需要告诉 GitHub「我的站点是谁」。

  1. 浏览器打开 https://github.com/settings/developers

  2. 点 New OAuth App，填写：

    • Application name：Tabby Sync（随便写）

    • Homepage URL：https://tabby.example.com（换成你的域名）

    • Authorization callback URL（⚠️ 必须一字不差，结尾带斜杠）：

      https://tabby.example.com/api/1/auth/social/complete/github/

  3. 点 Register application

  4. 页面上会显示 Client ID，复制保存

  5. 点 Generate a new client secret 生成 Client Secret，立即复制保存（只显示一次）

⚠️ 这里有两个容易抄错的地方：

  1. 回调地址必须带 /api/1/auth/social/ 前缀。官方部署文档里写的是 https://你的域名/complete/github/，那是错的——实际代码把 social_django 挂在 api/1/auth/social/ 下，实测登录跳转时 GitHub 收到的 redirect_uri 就是 .../api/1/auth/social/complete/github/。写错会报 “The redirect_uri is not associated with this application”。
  2. 结尾的斜杠不能少。

五、部署 tabby-web 容器

建目录、写配置：

mkdir -p /root/data/docker_data/tabbycloud
cd /root/data/docker_data/tabbycloud
nano docker-compose.yml

粘贴以下内容（把两处 GitHub 的值换成上一步拿到的）：

services:
  tabby-web:
    image: ghcr.io/eugeny/tabby-web:latest
    container_name: tabbycloud
    restart: always
    ports:
      - '8000:8000'
    volumes:
      - ./data:/app-dist
    environment:
      - DATABASE_URL=sqlite:////app-dist/db.sqlite3
      - PORT=8000
      - DEBUG=False
      - APP_DIST_STORAGE=file:///app-dist
      - SOCIAL_AUTH_GITHUB_KEY=你的ClientID
      - SOCIAL_AUTH_GITHUB_SECRET=你的ClientSecret

几个关键的说明：

  • ./data:/app-dist：数据库（db.sqlite3）和网页版程序文件都存在宿主机 data/ 目录里，备份这个目录就等于备份了一切。
  • APP_DIST_STORAGE=file:///app-dist 必须和挂载点一致，否则容器找不到版本文件。
  • 用 SQLite 而不是官方默认的 MariaDB，省一个容器；个人自用完全够。
  • 只想给内网用就别映射 8000:8000，改成 '127.0.0.1:8000:8000' 用反代访问。
  • nano 保存：Ctrl+O 回车，Ctrl+X 退出。

启动：

docker compose up -d

验证：

docker ps                # 应看到 tabbycloud 状态 Up
curl -s localhost:8000 | head -5   # 应输出一段 HTML

✅ 实测：容器启动时会自动执行数据库迁移（日志里是一串 Applying app.0001_initial... OK），data/db.sqlite3 自动创建，不需要手动初始化。

六、部署 Caddy（HTTPS 反向代理）

Caddy 的好处：自动申请和续期 Let’s Encrypt 证书，配置文件只有三行。

mkdir -p /root/data/docker_data/caddy
cd /root/data/docker_data/caddy
nano docker-compose.yaml

粘贴：

services:
  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - ./data:/data
      - ./config:/config
    networks:
      - tabby_net

networks:
  tabby_net:
    external: true
    name: tabbycloud_default

💡 tabbycloud_default 是上一步 docker compose up 自动创建的网络（规则：目录名 + _default）。Caddy 加入同一网络后可以直接用容器名 tabbycloud 访问它，不用暴露端口到公网。

创建反代配置：

nano Caddyfile

粘贴（域名换成你的）：

tabby.example.com {
    reverse_proxy tabbycloud:8000
}

启动：

docker compose up -d

验证：浏览器打开 https://tabby.example.com，应该看到 Tabby 首页（标题是 “Tabby - a terminal for a more modern age”）。第一次访问证书签发需要几秒到几十秒。

⚠️ 如果页面打不开，先看 docker logs -f caddy：常见是域名解析还没生效（Caddy 申请证书失败会明确报 DNS 问题）。

七、安装 Tabby 网页版程序包（关键，且有个坑）

tabby-web 容器本身只是一个后端，必须再装 Tabby 应用本体，否则网页会提示：

You haven't added any Tabby versions, see here

💡 为什么是空的？镜像里其实预装了一个版本，但 ./data:/app-dist 这个挂载把镜像内的目录覆盖掉了，所以看上去只有 db.sqlite3。必须自己装一次。

  1. 查最新稳定版本号：打开 https://www.npmjs.com/package/tabby-web-container ，只取不带 -nightly 的版本号（目前最新稳定版是 1.0.163）。

  2. 服务器上执行（版本号换成你查到的）：

    docker exec tabbycloud /manage.sh add_version 1.0.163

    会依次下载 tabby-core、tabby-terminal 等 10 个包，输出一列 INFO Downloading tabby-core@1.0.163 ...，跑完约 1–2 分钟。

  3. 看结果：

    ls /root/data/docker_data/tabbycloud/data/

⚠️ 坑一：装完版本文件多套了一层目录（实测必现）

正常情况下 data/1.0.163/ 下面应该是 tabby-core、tabby-web、tabby-terminal 这些目录。但当前镜像里 add_version 在本地存储模式下会把内容多套一层随机名字的目录，实测变成：

data/1.0.163/tmps9p47cj_/tabby-core
data/1.0.163/tmps9p47cj_/tabby-web
...

后果：程序按 data/1.0.163/tabby-core/... 找文件，全部 404，网页版终端一直转圈，接口还会返回一个怪怪的插件列表：

$ curl -s localhost:8000/api/1/versions
[{"version":"1.0.163","plugins":["tmps9p47cj_"]}]

正常的应该是 8 个插件名（tabby-core、tabby-settings、tabby-terminal、tabby-ssh、tabby-serial、tabby-telnet、tabby-community-color-schemes、tabby-web）。

判断方法：看目录里是不是只有一个 tmpXXXXXXXX 这样的子目录。

修复（把内层内容移上来一层，删掉空壳目录）：

docker exec tabbycloud sh -c 'cd /app-dist/1.0.163 && inner=$(ls -1 | head -1) && mv $inner/* . && rmdir $inner && ls -1'

修完后重启容器，插件列表就正常了：

docker restart tabbycloud
curl -s localhost:8000/api/1/versions

✅ 实测对照：修复前请求 http://你的地址/app-dist/1.0.163/tabby-web/dist/index.js 返回 404；修复后返回 200（1,025,796 字节）。这一步不修，后面全都不通。

版本列表接口有 60 秒缓存

/api/1/versions 带 60 秒页面缓存。刚装完版本看到空列表或旧列表，等一分钟或 docker restart tabbycloud 即可，不是装失败。

八、首次登录，拿同步令牌（token）

  1. 打开 https://tabby.example.com，点右上角 Log in → GitHub，授权后跳回站点。
  2. 打开站点里的设置（齿轮图标）。
  3. 弹窗里能看到：
    • GitHub account：你连接的账号
    • Config sync 一栏里的 Sync token for the Tabby app，那就是桌面客户端的同步令牌，点旁边的按钮复制。

💡 看不到齿轮 = 没登录成功。回去检查第四步的 callback URL 是否和你的域名完全一致（含 /api/1/auth/social/ 前缀和结尾斜杠）。

令牌也可以直接从接口取（同一个令牌，方便开机就存到密码管理器里）：

curl -s -H 'Authorization: Bearer 你的令牌' https://tabby.example.com/api/1/user

返回的 JSON 里 config_sync_token 字段就是它（128 位十六进制字符串）。这条命令同时也是验证令牌是否有效的办法：有效返回用户信息，无效返回 403。

九、桌面版 Tabby 配置同步（坑二在这里）

在电脑的 Tabby 客户端里：打开设置（Ctrl+, / Cmd+,）→ 找到 Config sync（配置同步）标签页。

  1. Sync host（同步主机）填：https://tabby.example.com
  2. Secret sync token（密钥同步令牌）粘贴第八步复制的令牌

⚠️ 坑二：Sync host 千万不能带 /api 后缀。

不少网上教程会告诉你填 https://tabby.example.com/api，那是错的。客户端内部是拿这个地址拼 /api/1/configs、/api/1/user，你再加个 /api 就变成 /api/api/1/configs，直接 404，表现为「连接测试一直转圈」或 Sync 报错。

另外：必须 https。客户端源码里硬性检查协议，填 http:// 会直接抛错 Config sync host must use HTTPS——这不是可用开关关掉的选项，是要防有人中间人改你的配置（配置里的 profile 命令是会被终端执行的）。

  1. 地址和令牌填对后，客户端会自动测试连接。连接成功后下方出现配置列表，第一次用要点 Upload as a new config（作为新配置上传），给它起个名字（比如「我的电脑」）。
  2. 之后这个配置行上会有四个按钮：
    • Upload：上传本机配置覆盖远端
    • Replace：把这一行设为本机当前同步目标（远端内容会被覆盖）
    • Download：下载远端配置覆盖本机
    • Delete：删除远端这份配置
  3. 出现 Sync automatically（自动同步）开关后打开：本机配置一改就自动上传，并且每分钟检查一次远端是否有更新、有则自动下载。

只想同步一部分内容？切到同一页的 Advanced（高级）标签，三个开关：

  • Sync hotkeys：快捷键
  • Sync window settings：窗口 / 外观设置
  • Sync Vault：Vault 里存的密码

💡 如果配置启用了 Vault 加密，部分同步不可用（界面会提示 Partial config sync is not possible when the config is encrypted via Vault.），此时整份配置一起同步。

在第二台电脑上：同样填 Sync host + 令牌，连接成功后不要再「Upload as a new config」，直接在已有配置行点 Download，配置就全过来了。

十、日常维护

更新网页版到新版本（先查 npm 最新稳定版本号，再）：

docker exec tabbycloud /manage.sh add_version 新版本号

装完按第七节检查一下有没有多套一层目录，有就 mv 修一下。

重置同步令牌（怀疑泄露 / 想作废旧 key）：

docker exec tabbycloud sh -c "cd /app && PY=\$(ls -d /venv/*/bin/python | head -1) && \$PY manage.py shell <<'PYEOF'
from tabby.app.models import User
u = User.objects.get(username='你的用户名')
u.config_sync_token = ''
u.save()
u.refresh_from_db()
print(u.config_sync_token)
PYEOF"

✅ 实测：这条命令原样可跑（镜像内 Django 3.2.12）。模型层的 save() 检测到空值会自动生成新令牌，所以打印出来的就是新令牌；旧令牌立即失效（同一时刻用它请求 /api/1/user 返回 403）。拿到新令牌后去站点设置里看，或直接填到桌面端。

备份数据（整个站点就一个目录，含数据库和版本文件）：

tar czf tabby-backup-$(date +%F).tar.gz -C /root/data/docker_data/tabbycloud data

查看日志 / 重启：

docker logs -f tabbycloud          # 实时日志
docker compose restart             # 在 tabbycloud 目录下执行

升级 tabby-web 镜像：

cd /root/data/docker_data/tabbycloud
docker compose pull && docker compose up -d

💡 升级镜像后如果发现版本列表空了，是正常现象——data/ 目录一直在，重新 add_version 一次即可。

同步接口（桌面端实际走的路径）

GET  /api/1/user            Authorization: Bearer <128 位令牌>  → 200，返回 config_sync_token
POST /api/1/configs         {"name":"Test Desktop"}            → 201，创建一份配置
PATCH /api/1/configs/1      {"content":"profiles: []"}         → 200，内容写入成功
GET  /api/1/user            令牌错误                             → 403
重置令牌后旧令牌再次请求                                          → 403（立即失效）

结论：整条链路（容器 → SQLite → GitHub OAuth 回调 → 版本分发 → Bearer 令牌同步）在本地实测通透；仅 HTTPS 证书签发与 GitHub 真实登录需要在有域名的服务器上完成，这两步依赖你的域名，文中已给出验证方法。
