RouterOS 动态 IPv6 公网端口绑定服务器：脚本与定时更新小白教程

按步骤把 IPv6 公网服务端口绑定到指定服务器，通过 PD 前缀与固定地址后缀生成 /128 地址列表，配置脚本、每分钟更新、验证和故障处理。

家里已经有公网 IPv6，服务器也能通过 SLAAC 自动拿到地址，但宽带重新拨号后公网前缀可能变化。此时既不想把防火墙目标地址写死，也不应该只按端口放行整个 LAN。

这篇教程按照实际配置顺序，把公网服务绑定到两台指定服务器，并让 RouterOS 每分钟更新目标地址。现场验证版本为 RouterOS 7.25.1。示例中的接口名、端口和服务器角色沿用本次部署；IPv6 地址后缀使用虚构示例，必须替换后再执行。

第 1 步：先确认这套方法是否适合你的网络

本教程的前提是：RouterOS 已经能通过 DHCPv6-PD 获取前缀，并把其中一个 /64 配到 LAN；服务器已经有可用的公网 IPv6；现有 IPv6 防火墙能正常保护 LAN。

如果还没有完成 IPv6 基础配置，先阅读RouterOS IPv6 配置教程。本文只处理服务器端口绑定，不重新配置拨号、PD、RA、DNS 或整份防火墙。

示例环境如下：

项目示例值
RouterOS LAN 网关10.20.20.1
LAN bridgebridge1
IPv6 DHCP Client 所在接口pppoe-out1
互联网入口接口列表WAN，已包含 pppoe-out1
Matrix / Synapse 全套服务10.20.20.8 对应的虚拟机
Shadowsocks 服务10.20.20.10 对应的虚拟机

这里的 IPv4 地址只是帮助辨认服务器。IPv6 防火墙实际匹配的是服务器的 公网 IPv6 /128 地址，不会把 IPv6 流量转换到这个 IPv4 地址。

在 WinBox 的 New Terminal 中依次输入：

/interface list member print
/ipv6 dhcp-client print detail
/ipv6 address print detail
/ipv6 firewall filter print detail

检查以下条件：

  1. DHCPv6 Client 的状态为 bound，并记录它所在的接口。
  2. bridge1 上有来自该 Client 地址池的公网 /64 地址，from-pool 有值。
  3. WAN 列表确实包含互联网入口接口。
  4. IPv6 forward 链具有 established/related 放行、invalid 丢弃、必要的 ICMPv6、LAN 出站放行，以及末尾的拒绝规则。

本文脚本从 DHCPv6 Client 读取地址池名称，再找到 LAN 地址。因此不用把动态公网前缀或地址池名称写死。若你的接口名不同，后面的脚本和命令也要修改。

第 2 步：到两台服务器上确认公网 IPv6 和固定后缀

分别登录 Matrix 和 SS 虚拟机，输入以下 Linux 命令：

ip -6 addr show scope global
ss -lntup

第一条查看地址，第二条检查服务是否监听预期端口和 IPv6 地址。Docker 服务还需要在宿主机侧正确发布 IPv6 端口。

例如看到下面这个文档示例地址：

2001:db8:aaaa:bbbb:1234:5678:abcd:8/64

它可以拆成两部分：

部分示例
当前公网 /64 前缀2001:db8:aaaa:bbbb::/64
服务器后 64 位，简称 IID1234:5678:abcd:8
脚本里的 IID 写法::1234:5678:abcd:8

2001:db8::/32 是文档专用地址，不能用于实际公网连接。请记录你机器上的真实 IID。

必须使用稳定且不会随公网前缀变化的 IID。 本次虚拟机使用了与网卡相关的固定后缀，并已核对实际连接。不要选择标有 temporary 的临时地址；RFC 7217 的 stable privacy 地址会在前缀变化时生成不同 IID（见 RFC 7217）。不能仅凭“当前有公网 IPv6”就认定后缀固定。

本教程不要求在 PVE 中额外填写一个 ULA。服务器已经有可用公网 IPv6 且 IID 固定时，直接使用它即可。更换虚拟网卡 MAC、重建虚拟机或改变服务器 IPv6 地址生成方式后，需要重新核对 IID。

第 3 步：先保存备份，再打开 Safe Mode

回到 RouterOS Terminal，输入：

/system backup save name=before-ipv6-server-binding
/export terse file=before-ipv6-server-binding
/ipv6 export terse file=before-ipv6-server-binding-ipv6
/file print where name~"before-ipv6-server-binding"

WinBox 的 Files 中应出现 .backup 和 .rsc 文件。完整导出里包含后续恢复所需的接口、脚本和定时任务；单独的 /ipv6 export 不包含 /system script 和 /system scheduler。

然后在 Terminal 中按一次 Ctrl+X。看到以下提示再继续：

Taking Safe Mode session... Success!
[用户名@路由器名] <SAFE>

不要连续按两次：第二次会退出 Safe Mode。整个配置过程中保持这个会话连接。

第 4 步：建立两个只包含单台服务器的地址列表

先检查同名列表是否存在：

/ipv6 firewall address-list print where list="published-matrix-v6"
/ipv6 firewall address-list print where list="published-ss-v6"

下面两条 add 命令只在首次安装、同名列表不存在时执行一次。 已完成配置的路由器应跳过，不要重复添加。

/ipv6 firewall address-list
add list=published-matrix-v6 address=::1 comment=managed-published-matrix
add list=published-ss-v6 address=::1 comment=managed-published-ss

这里暂时使用回环地址 ::1 作占位。此时还没有修改端口规则；后面的脚本会把它替换成真实服务器公网地址。绝不能为了省事把整个 /64 填进去，否则仍然是在向整个网段开放端口。

第 5 步：创建根据 PD 前缀更新地址列表的脚本

先检查脚本是否已经存在：

/system script print proplist=name where name="update-published-ipv6"

首次安装时，把下面完整代码复制到文本编辑器，先替换最后部分的两条 IID：

::1234:5678:abcd:8   → Matrix 服务器真实的固定 IID
::1234:5678:abcd:10  → SS 服务器真实的固定 IID

同时核对脚本里的 pppoe-out1 和 bridge1 是否是你第 1 步确认的接口。然后将修改后的整个代码框粘贴到 RouterOS Terminal 执行：

/system script add name=update-published-ipv6 policy=read,write source={
    # 读取不到正确前缀时，将目标改为回环地址并明确报错。
    :local deny do={
        :foreach n in={"published-matrix-v6";"published-ss-v6"} do={
            :local ids [/ipv6 firewall address-list find where list=$n]
            :if ([:len $ids]=1) do={
                :if ([/ipv6 firewall address-list get $ids address]!="::1/128") do={
                    /ipv6 firewall address-list set $ids address=::1
                }
            }
        }
        :log error ("event=published_ipv6_update reason=" . $reason)
        :error $reason
    }

    # 每个列表必须恰好只有一个目标，防止重复配置扩大放行范围。
    :local m [/ipv6 firewall address-list find where list="published-matrix-v6"]
    :local s [/ipv6 firewall address-list find where list="published-ss-v6"]
    :if (([:len $m]!=1) || ([:len $s]!=1)) do={
        :error "Published IPv6 lists must contain exactly one host each"
    }

    # 从拨号接口的 DHCPv6 Client 读取地址池，再找到 LAN 的地址。
    :local client [/ipv6 dhcp-client find where interface="pppoe-out1"]
    :if ([:len $client]!=1) do={
        $deny reason="missing-dhcp-client"
    }
    :local pool [/ipv6 dhcp-client get $client pool-name]
    :local ids [/ipv6 address find where interface=bridge1 and from-pool=$pool]
    :if ([:len $ids]!=1) do={
        $deny reason="missing-lan-prefix"
    }
    :local text [/ipv6 address get $ids address]
    :local slash [:find $text "/"]
    :if ([:pick $text ($slash+1) [:len $text]]!="64") do={
        $deny reason="lan-prefix-not-64"
    }

    # 保留前 64 位，只接受公网单播前缀。
    :local prefix ([:toip6 [:pick $text 0 $slash]] & ffff:ffff:ffff:ffff::)
    :if (($prefix in 2000::/3)=false) do={
        $deny reason="lan-prefix-not-global"
    }

    # 必须把下面两个示例 IID 改成自己服务器的固定后缀。
    :local matrix ($prefix | ::1234:5678:abcd:8)
    :local ss ($prefix | ::1234:5678:abcd:10)

    # address 属性返回带 /128 的字符串；只有地址变化时才写入。
    :if ([/ipv6 firewall address-list get $m address]!=([:tostr $matrix] . "/128")) do={
        /ipv6 firewall address-list set $m address=$matrix
        :log info "event=published_ipv6_update host=matrix updated=yes"
    }
    :if ([/ipv6 firewall address-list get $s address]!=([:tostr $ss] . "/128")) do={
        /ipv6 firewall address-list set $s address=$ss
        :log info "event=published_ipv6_update host=ss updated=yes"
    }
}

这个版本的脚本按现场实际运行代码整理，只使用 read,write 权限。它不会更改 DHCPv6-PD、RA、服务器地址或 DNS。

如果长段粘贴不方便，可以在 WinBox 的 System → Scripts → New 中创建：Name 填 update-published-ipv6，Policy 选择 read、write，Source 只粘贴 source={...} 外层大括号里面的脚本正文，点击保存。两种方法二选一。

第 6 步：先手动运行，确认地址正确，再碰防火墙

依次输入：

/system script run update-published-ipv6
/ipv6 firewall address-list print detail where list="published-matrix-v6"
/ipv6 firewall address-list print detail where list="published-ss-v6"
/system script print proplist=name,run-count,last-started where name="update-published-ipv6"

应看到每个列表各有一个真实公网地址，精确到 /128，且分别与 Matrix、SS 服务器的地址一致。若仍为 ::1/128、地址不一致或出现报错，先修正接口、PD 状态或 IID，不要继续绑定规则。

可以在 RouterOS 上输入以下命令，但先替换尖括号中的地址：

/ping <Matrix服务器的真实公网IPv6> count=3
/ping <SS服务器的真实公网IPv6> count=3

从 LAN 电脑也应确认服务端口可连接。macOS 示例：

nc -6 -vz -G 4 <Matrix服务器的真实公网IPv6> 12335
nc -6 -vz -G 4 <SS服务器的真实公网IPv6> 18388

Ping 不通也可能是服务器自身禁止 ICMP，不能仅据此认定服务不可用；端口测试同样需要服务器和 Docker 正确监听 IPv6。

第 7 步：把现有公网端口规则绑定到对应列表

本次需要绑定的端口如下，只有你实际使用的服务才应开放：

服务器协议端口
Matrix / Synapse 虚拟机TCP12335、12336、12337、12338、10521、17882
同一台 Matrix 虚拟机上的 coturnTCP、UDP3478
同一台 Matrix 虚拟机上的中继服务UDP50000-50400
SS 虚拟机TCP18388

本次原有防火墙里，Matrix 部分是 9 条规则、SS 部分是 1 条。下面通过既有 comment 找到它们。先输入只读命令查看：

/ipv6 firewall filter print detail where comment~"12335|12336|12337|12338|10521|17882|^allow coturn"
/ipv6 firewall filter print detail where comment~"18388"

必须逐条确认显示的都是你要修改的公网服务规则，并且数量为 9 和 1。注释不同、端口不同、存在重复规则时，先调整匹配条件；不要靠“数量正好一样”代替核对内容。

确认后输入：

{
    :local m [/ipv6 firewall filter find where comment~"12335|12336|12337|12338|10521|17882|^allow coturn"]
    :local s [/ipv6 firewall filter find where comment~"18388"]
    :if (([:len $m]!=9) || ([:len $s]!=1)) do={
        :error "Unexpected public service rule count"
    }
    /ipv6 firewall filter set $m dst-address-list=published-matrix-v6 in-interface-list=WAN out-interface=bridge1
    /ipv6 firewall filter set $s dst-address-list=published-ss-v6 in-interface-list=WAN out-interface=bridge1
}

上面是一个完整的命令块，连同最外层 { 和 } 一起粘贴执行。 外层作用域让两条 :local 变量保留到该命令块结束；不要遗漏大括号后再逐条执行。

这一步在原位置修改规则，不移动最终 drop，也不新增广泛放行规则。效果是公网流量必须同时匹配正确的协议、端口、服务器 /128 目标和 WAN → LAN 方向。

第 8 步：如果原来没有这些规则，按这个分支新建

已经完成第 7 步的人跳过本节。 此分支只适合没有原服务放行规则、但已有完整基础防火墙和最终拒绝规则的路由器。

先确定最终拒绝规则的 comment。以下假设它恰好是 11. Drop all other forward (Protect LAN)，并且只有一条：

/ipv6 firewall filter print detail where comment="11. Drop all other forward (Protect LAN)"

核对后在它前面添加四条规则。端口相同的规则作了合并，作用与前面的十条相同：

/ipv6 firewall filter
add chain=forward action=accept in-interface-list=WAN out-interface=bridge1 dst-address-list=published-matrix-v6 protocol=tcp dst-port=12335-12338,10521,17882,3478 comment="Published Matrix TCP" place-before=[find comment="11. Drop all other forward (Protect LAN)"]
add chain=forward action=accept in-interface-list=WAN out-interface=bridge1 dst-address-list=published-matrix-v6 protocol=udp dst-port=3478 comment="Published Matrix STUN UDP" place-before=[find comment="11. Drop all other forward (Protect LAN)"]
add chain=forward action=accept in-interface-list=WAN out-interface=bridge1 dst-address-list=published-matrix-v6 protocol=udp dst-port=50000-50400 comment="Published Matrix relay UDP" place-before=[find comment="11. Drop all other forward (Protect LAN)"]
add chain=forward action=accept in-interface-list=WAN out-interface=bridge1 dst-address-list=published-ss-v6 protocol=tcp dst-port=18388 comment="Published SS TCP" place-before=[find comment="11. Drop all other forward (Protect LAN)"]

不要把新规则追加到最终拒绝规则后面。也不要保留更早的同端口、未绑定目标的宽泛 accept：数据包如果已经被前面的规则放行，后面的精确规则无法收紧它。

第 9 步：建立每分钟运行的定时任务

先检查名称，确保首次安装时没有同名任务：

/system scheduler print where name="update-published-ipv6"

然后输入一次：

/system scheduler add name=update-published-ipv6 interval=1m start-time=startup policy=read,write on-event="/system script run update-published-ipv6"

输入以下命令查看执行次数和下次执行时间：

/system scheduler print proplist=name,run-count,next-run where name="update-published-ipv6"
/system script print proplist=name,run-count,last-started where name="update-published-ipv6"

等待约一分钟后再查看，Scheduler 的 run-count 应增加。脚本会重新读取当前 LAN 前缀，但只有目标地址改变时才写入地址列表，不会每分钟重复新增条目。

定时任务保存在 ROS 中，重启后仍然存在。根据 MikroTik Scheduler 文档，start-time=startup 与非零 interval 组合不会在启动瞬间额外执行一次，而是按周期运行。因此首次配置要先手动运行脚本；也不能假定开机时 PD 已经就绪：地址池尚未就绪时脚本会报错并关闭这两个目标的新增入站放行，后续定时执行在前缀恢复后重新更新。

第 10 步：完整核对一次规则、地址、日志和连通性

在 RouterOS 输入：

/ipv6 firewall address-list print detail
/ipv6 firewall filter print detail where chain=forward
/system scheduler print proplist=name,run-count,next-run where name="update-published-ipv6"
/log print where topics~"error" and message~"published"

重点检查：

  1. 两个地址列表各只有一个 /128 公网地址，且属于对应服务器。
  2. 每条服务规则带有正确的 dst-address-list、in-interface-list=WAN、out-interface=bridge1。
  3. 服务规则位于最终 forward drop 之前；更早没有同端口的宽泛放行。
  4. Scheduler 已实际运行，没有权限或脚本错误。
  5. IPv6 出网、RouterOS 管理和服务本身仍正常。

LAN 内端口能连接，只能证明服务器在内网可达。验证公网入站必须使用一个真正位于外网且具有 IPv6 的客户端，例如关闭 Wi-Fi 后具备 IPv6 的移动网络，或你自己的外部 IPv6 主机。公网客户端必须访问服务器本身的公网 IPv6 或正确的 AAAA 域名。

从外网连接某台其他 LAN 设备的同一端口，应被最终 drop 拒绝。UDP 服务还需要用对应的 STUN/TURN、通话或业务客户端验证，不能用一次 TCP 连接测试替代。

现场配置验证了地址生成、占位地址恢复、重复运行不增加条目、定时任务实际执行两次，以及 LAN 中 Matrix、SS、WinBox 和 IPv6 出网可用；没有为了测试而强制宽带重拨，也没有完成独立公网客户端的入站测试。

第 11 步：确认后退出 Safe Mode，并保存完整导出

确认配置和测试结果后，在当前 Terminal 再按一次 Ctrl+X，看到：

Releasing Safe Mode... Success!
Safe Mode released

再输入：

/export terse file=after-ipv6-server-binding
/ipv6 export terse file=after-ipv6-server-binding-ipv6
/file print where name~"after-ipv6-server-binding"

完整 .rsc 包含脚本和 Scheduler。下次迁移机器时，不能只导入 /ipv6 部分：还要核对接口列表、DHCPv6 Client、脚本中的 IID、脚本权限和定时任务。

第 12 步：出现问题时按这个顺序处理

现象或报错先检查什么
missing-dhcp-client脚本中的 pppoe-out1 是否正确，是否有且仅有一个 Client
missing-lan-prefixClient 是否 bound；LAN 是否存在来自其地址池的地址
lan-prefix-not-64本教程要求服务器所在 LAN 使用一个 /64
lan-prefix-not-global是否拿到了有效公网前缀，而不是 ULA
列表里仍为 ::1/128看上述错误，并手动运行脚本定位；不要改成整段 /64 放行
Unexpected public service rule count先核对规则 comment 和重复项，不能无条件去掉数量检查
地址正确但服务不通检查服务器监听、Docker、服务器防火墙、AAAA 记录和外网 IPv6
更换网卡或重装后失效重新确认实际 IID，更新脚本中的两个后缀

需要临时暂停自动更新时输入：

/system scheduler disable [find name="update-published-ipv6"]

修复后先手动运行，再恢复定时任务：

/system script run update-published-ipv6
/system scheduler enable [find name="update-published-ipv6"]

暂停任务不会自动把防火墙恢复成“整个 LAN 按端口放行”。要彻底回滚，应在本地管理连接下对照修改前导出逐项恢复；二进制 .backup 恢复属于整机回滚，会覆盖配置并重启，应确认设备、版本和恢复入口后再操作。

动态前缀变化时，到底会更新哪些东西？

宽带重拨后，ROS 重新获得 PD，LAN 的公网前缀改变；服务器通过 SLAAC 获得新前缀下的地址；在 IID 不变的前提下，定时脚本生成新的完整 /128 目标并更新防火墙列表。

这只是防火墙目标地址更新，不会替服务器获取 IPv6，也不会自动更新 DNS 的 AAAA 记录。外网如果使用域名访问，还要保证你自己的 DDNS 或域名更新机制正常。实际恢复时间还会受到 SLAAC 和 DNS 缓存影响，不能只按一分钟的防火墙检查周期估算。

IPv6 也不会按端口自动寻找服务器。以前能访问，是因为请求本来就发往正确的服务器 IPv6，而宽泛规则允许了这类流量。现在多加一层目标 /128 限制，其他 LAN 设备的相同端口就不会因此一起被开放。

参考：MikroTik Scripting、IPv6 地址与 SLAAC、Firewall Address Lists。
