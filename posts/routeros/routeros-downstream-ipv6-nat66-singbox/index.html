二级 RouterOS IPv6 完整配置：RA/SLAAC、DHCPv6-PD 与防火墙

从上游 RA/SLAAC 到 DHCPv6-PD，将 IPv6 前缀安全地分配到二级 ROS 的 LAN，让设备通过 SLAAC 获取公网 IPv6；包含 ULA + NAT66 备用方案、完整防火墙、sing-box 和验证命令。

本文按步骤介绍二级 RouterOS 的 IPv6 配置，分成两种上游条件：

  1. 上游只发布 RA/SLAAC，没有委派前缀：二级 ROS 从 WAN 的 RA 获取 IPv6 地址和默认路由；LAN 使用 ULA + NAT66，适合出站访问 IPv6 网站。
  2. 上游支持 DHCPv6-PD：二级 ROS 从 WAN/PPPoE 获取委派前缀，将其中一个 /64 配给 LAN 并通过 RA 通告。LAN 设备各自通过 SLAAC 获得公网可路由的 GUA，出站不需要 NAT66。

RA 告诉路由器上游网关和本链路前缀；DHCPv6-PD 才会把可路由前缀委派给下游。若希望 LAN 设备各有公网 IPv6，必须由运营商或上游路由器向二级 ROS 委派前缀，或静态路由一段独立前缀；不能把 WAN 上同一段 /64 直接复制到 LAN。

执行前将 ether1、bridge1、pppoe-out1 替换为实际接口名。先确认上游提供 RA、DHCPv6-PD，还是两者都有，再选择对应章节。

1. 网络结构与替换项

本文沿用当前环境的 LAN 地址规划。示例接口名 ether1、bridge1 必须替换成你的实际 WAN、LAN 接口名；不要把命令原样套到接口名不同的 ROS 上。

设备 / 接口示例配置说明
上游 ROS 的下游口接入下游 WAN 的二层网段在该接口上发布上游 IPv6 RA
二级 ROS WANether1从上游 RA 学到 IPv6 地址/默认路由
二级 ROS LANbridge1，IPv4 网关 10.0.0.1/24LAN bridge，成员端口按现有 IPv4 配置
二级 ROS LAN IPv6fd88:1::1/64ULA 网关并发布 SLAAC 前缀
LAN IPv6 前缀fd88:1::/64客户端自动生成的内网 IPv6 地址
可选 sing-box VM10.0.0.6、fd88:1::6/64仅用于后文选择性代理

fd88:1::/64 是本文环境采用的示例 ULA。ULA 只在内网使用，不会由公网路由；请先确认没有和现有隧道或其他 LAN 前缀冲突。若网络已有自己的 ULA，就统一替换下文的前缀和网关地址。

开始前先在下游 ROS Terminal 备份并确认接口名称：

/export file=before-ipv6
/interface print detail
/interface list member print detail
/ipv6 settings print
/ipv6 firewall filter print detail
/ipv6 firewall nat print detail

建议通过 WinBox 的 Safe Mode 或在本地 LAN 侧操作，避免接口、RA 或防火墙设置错误后失去管理连接。本文只配置 IPv6，不更改已有 IPv4 地址、DHCP、NAT 或 IPv4 防火墙。

2. 检查上游 IPv6 和接口

先在上游 ROS 确认它本身有可用 IPv6 默认路由，且连接二级 ROS WAN 的接口已启用 Neighbor Discovery / RA：

/ipv6 address print detail
/ipv6 nd print detail
/ipv6 nd prefix print detail
/ipv6 route print detail where dst-address="::/0"

再在二级 ROS 确认接口名和现有 IPv6 配置：

/interface print detail
/interface list member print detail
/ipv6 settings print
/ipv6 address print detail
/ipv6 dhcp-client print detail
/ipv6 route print detail
/ipv6 nd print detail
/ipv6 firewall filter print detail
/ipv6 firewall nat print detail

记下实际 WAN（例如 ether1 或 pppoe-out1）和 LAN bridge（例如 bridge1）。先备份，并在 LAN 侧保持 WinBox 管理连接：

/export file=before-ipv6
/system backup save name=before-ipv6

不要清空现有防火墙，也不要重复添加已存在的地址、DHCPv6 client、ND 或 NAT 规则。

3. WAN 获取 IPv6：按上游能力选择

3.1 上游发送 RA：WAN 用 SLAAC 获取地址和默认路由

RouterOS 开启 IPv6 转发时，默认的 RA 接收模式可能是 yes-if-forwarding-disabled，作为路由器时不会接受上游 RA。若上游通过 RA 提供 WAN 地址和默认路由，设置：

/ipv6 settings set accept-router-advertisements=yes

修改 IPv6 Settings 后按 RouterOS 提示重启，再检查：

/ipv6 address print detail
/ipv6 route print detail where dst-address="::/0"
/ping address=2606:4700:4700::1111 count=4

期望 WAN 出现动态 global IPv6 地址和 active 的 ::/0 默认路由，网关通常是上游 link-local 地址，例如 fe80::…%ether1。若只有 fe80:: 链路本地地址、没有动态地址或默认路由，先排查上游 RA 是否送到正确 VLAN/接口；不要继续配置 NAT66 或 LAN GUA。

RA/SLAAC 只让二级 ROS 在 WAN 链路上获得地址和默认路由，不会把上游 /64 委派给 LAN。只有这种上游服务时，使用第 4.1 节的 ULA + NAT66 方案。

3.2 上游支持 DHCPv6-PD：请求可切分的前缀

PPPoE 环境中，DHCPv6-PD client 应绑定到实际 PPPoE 接口；非 PPPoE 则绑定到承载 DHCPv6 的 WAN/VLAN 接口。确认运营商提供 Prefix Delegation 后，执行：

/ipv6 dhcp-client add interface=pppoe-out1 request=prefix pool-name=wan-pd pool-prefix-length=64 use-peer-dns=no comment="ISP DHCPv6 prefix delegation"
/ipv6 dhcp-client print detail
/ipv6 pool print detail

将 pppoe-out1 换成实际 WAN。成功时 client 状态应为 bound 并显示 prefix=…；pool 的 prefix-length=64。比如 ISP 委派 /60 时，pool 可切出多个 /64，其中一个分给 LAN。

DHCPv6-PD 负责委派前缀，不等于默认路由。 默认路由可能由 PPPoE 或上游 RA 提供。若该线路通过 RA 发布默认路由，仍要设置 accept-router-advertisements=yes 并确认 ::/0 存在。若 status=searching 或没有 prefix，请向运营商确认是否开通 PD 及 WAN 接口是否正确。

4. 给 LAN 分配 IPv6 前缀并发布 RA

检查并禁用 RouterOS 默认的全接口 ND/RA 项，避免意外在 WAN 发布 LAN 前缀；只在 LAN bridge 发布：

/ipv6 nd print detail
/ipv6 nd set [find default=yes] disabled=yes
/ipv6 nd add interface=bridge1 advertise-dns=no managed-address-configuration=no other-configuration=no comment="LAN IPv6 Router Advertisement"

若已有 interface=bridge1 的 ND 项，修改现有项，不要重复新增。确认 ND 只在 LAN/VLAN 接口发布。

4.1 没有 DHCPv6-PD：ULA + NAT66 出站

没有可路由的下游前缀时，在 LAN bridge 配置 ULA 网关并通过 RA 发布：

/ipv6 address add address=fd88:1::1/64 interface=bridge1 advertise=yes comment="LAN ULA gateway"

将 fd88:1::/64 换成没有与 VPN、隧道或其他 LAN 冲突的 ULA 前缀。客户端通过 SLAAC 取得 ULA 地址和默认路由；此模式不需要 DHCPv6 server。

确认 WAN 已有可用 IPv6 地址和默认路由，再检查 NAT：

/ipv6 firewall nat print detail

若没有等效规则，只为这个 LAN ULA 网段增加出站 NAT66：

/ipv6 firewall nat add chain=srcnat src-address=fd88:1::/64 out-interface=ether1 action=masquerade comment="NAT66 LAN ULA to WAN"

把 ether1 换成实际 WAN。NAT66 只转换 LAN 主动发起的出站连接；它不会使 LAN 设备获得公网 GUA，也不能替代防火墙。

4.2 有 DHCPv6-PD：委派前缀分给 LAN，设备使用公网 GUA

确认第 3.2 节的 DHCPv6 client 已 bound，且 wan-pd pool 的 prefix-length=64。从 pool 为 LAN bridge 分配一个 /64，并设 advertise=yes：

/ipv6 address add address=::1/64 from-pool=wan-pd interface=bridge1 advertise=yes comment="LAN GUA from DHCPv6-PD"

RouterOS 从动态委派池取一个 /64，并在 LAN RA 中通告。保持 LAN ND 的 managed-address-configuration=no 和 other-configuration=no：客户端使用 SLAAC 自行生成 GUA，不需要 DHCPv6 server。检查：

/ipv6 address print detail where interface=bridge1
/ipv6 nd prefix print detail where interface=bridge1
/ipv6 route print detail

客户端应获得运营商委派前缀内的 global IPv6 地址和默认路由。各设备的 GUA 可由公网路由到家中，但下面的防火墙仍默认阻止公网主动连接；确有需要时，只为特定设备/端口添加最小范围的入站允许规则。

此模式不需要 NAT66。若还要给 sing-box VM 或内网服务保留稳定 ULA，可在 LAN 同时发布 ULA 与 PD GUA：

/ipv6 address add address=fd88:1::1/64 interface=bridge1 advertise=yes comment="LAN stable ULA"

双前缀时，GUA 用于正常公网 IPv6 通信，ULA 用于稳定的内部通信/指定下一跳。只有 ULA 源地址需要访问公网时，才额外添加第 4.1 节中按 ULA 网段限定的 NAT66 规则。不要对所有 IPv6 源地址无条件 masquerade。

5. IPv6 防火墙：允许必要控制流量，默认拒绝 WAN 入站

IPv6 不应依赖 NAT 提供安全性。防火墙要区分 input（访问 ROS 本机）和 forward（经过 ROS 的流量），允许连接回包、必要 ICMPv6、LAN 出站，并默认拒绝 WAN 到路由器及 LAN 的新连接。

先检查现有规则和顺序：

/ipv6 firewall filter print detail
/interface list print detail
/interface list member print detail

下面是空 IPv6 filter 表时的完整基线示例。已有规则要按相同策略整合并保证顺序，不要重复粘贴或清空现有规则。替换 bridge1、ether1 为实际 LAN/WAN：

/ipv6 firewall filter
add chain=input action=accept connection-state=established,related,untracked comment="IPv6 input established related"
add chain=input action=drop connection-state=invalid comment="IPv6 input drop invalid"
add chain=input action=accept protocol=icmpv6 comment="IPv6 input allow ICMPv6 RA ND PMTUD"
add chain=input action=accept in-interface=bridge1 comment="IPv6 input allow LAN management"
add chain=input action=accept in-interface=ether1 protocol=udp src-address=fe80::/10 dst-port=546 comment="IPv6 input allow DHCPv6 client replies"
add chain=input action=drop in-interface=ether1 comment="IPv6 input drop WAN access"
add chain=input action=drop comment="IPv6 input drop remaining"
add chain=forward action=accept connection-state=established,related,untracked comment="IPv6 forward established related"
add chain=forward action=drop connection-state=invalid comment="IPv6 forward drop invalid"
add chain=forward action=accept in-interface=bridge1 out-interface=ether1 comment="IPv6 forward LAN to WAN"
add chain=forward action=drop in-interface=ether1 comment="IPv6 forward drop unsolicited WAN"
add chain=forward action=drop comment="IPv6 forward drop remaining"

WAN 若为 pppoe-out1，将 ether1 替换为 pppoe-out1。DHCPv6-PD 模式要保留 WAN 入站 UDP 546 的 DHCPv6 client 回复规则；上游 RA、ND 和 PMTU 等必要控制流量由 ICMPv6 规则处理。不要无差别屏蔽 ICMPv6。

规则策略：

  • input 只接受已建立连接、ICMPv6、LAN 管理和必要 DHCPv6 client 回复；WAN 其他访问丢弃。
  • forward 只接受连接回包和 LAN 主动发往 WAN 的流量；WAN 主动发起的新连接和其他未授权转发丢弃。
  • LAN 设备有公网 GUA 不代表端口自动开放；需要入站服务时，逐条添加严格限定的规则，绝不允许所有 WAN 到 LAN。

需要 sing-box 选择性路由时，策略路由会通过 LAN bridge 把部分流量送到 VM，应按路由标记单独允许，并置于最终 drop 之前；不要用宽泛 LAN 到 LAN 放行。参照第 8 节。

7. 分层验证 IPv6

7.1 验证 WAN 上游路由

/ipv6 address print detail
/ipv6 dhcp-client print detail
/ipv6 pool print detail
/ipv6 route print detail where dst-address="::/0"
/ping address=2606:4700:4700::1111 count=4

RA-only 模式应在 WAN 看到动态 GUA 和活动 ::/0。PD 模式还应看到 DHCPv6 client 为 bound 且有委派 prefix；默认路由仍需单独验证。ROS 本机无法访问 IPv6 时，先修复上游地址/路由，不要排查 LAN NAT。

7.2 验证 LAN RA、前缀和客户端出站

在 RouterOS 检查：

/ipv6 address print detail where interface=bridge1
/ipv6 nd print detail
/ipv6 nd prefix print detail where interface=bridge1
/ipv6 firewall filter print stats
/ipv6 firewall nat print stats

在 Mac/Linux 客户端检查地址、默认路由，并绕过客户端显式代理做 IPv6-only 测试：

ifconfig
route -n get -inet6 default
curl --noproxy '*' -6 --connect-timeout 8 https://api6.ipify.org

Linux 可用 ip -6 address 和 ip -6 route。RA-only + NAT66 模式下，客户端应有 ULA；PD 模式下，客户端应有运营商委派前缀内的 GUA。若同时配置双前缀，设备可能同时显示 ULA 和 GUA。IPv6-only 测试成功时，公网看到的是 NAT66 出口地址（ULA 模式）或设备所用 GUA（PD 模式）。

排错顺序：

  1. DHCPv6 client 没有 bound/prefix：检查运营商是否提供 PD、client 是否绑定正确 WAN。
  2. ROS 没有活动 ::/0：检查上游 RA 或线路默认路由；PD 本身不是默认路由。
  3. LAN 设备没有地址：检查 bridge 上地址是否 advertise=yes、ND 是否启用，并重新连接客户端。
  4. 设备有地址却没有默认路由：检查 RA lifetime 和 LAN ND。
  5. ROS 可以访问、客户端不行：查看 forward 规则顺序/计数器；ULA 出站还要检查 NAT66 匹配和计数器。
  6. curl -6 结果不符预期：–noproxy ‘*’ 只绕过 Mac 上 curl 显式代理，不能绕过 ROS 透明分流。某些代理节点不提供 IPv6 出口，境外 IPv6 站点失败不一定是基础链路故障。

8. 可选：保留 sing-box 的 IPv6 选择性分流

只在已经配置并需要通过 sing-box 代理特定 IPv6 目标时执行本节。普通 LAN IPv6 直连和 NAT66 不依赖 sing-box。

本环境 Debian VM 使用 10.0.0.6、ULA fd88:1::6/64，ROS LAN 网关为 fd88:1::1。如果要让它承担 IPv6 下一跳，需要给虚拟机配置固定 ULA 地址和默认网关。

若采用 DHCPv6-PD 并沿用此 VM 的 ULA 地址，先按第 4.2 节在 LAN bridge 配置并通告 fd88:1::1/64；否则 VM 的 fd88:1::6 网关和 sing-box 下一跳没有对应的 LAN ULA 网段。若 LAN 只使用 PD 的 GUA，则需给 VM 配置委派前缀内的 GUA，并将 ROS 的 GUA 网关作为下一跳，不能照抄下方 ULA 配置。

在 PVE 网页界面填写

  1. 选择 VM 102，打开 Cloud-Init 页面。
  2. 双击 IP 配置（net0）。
  3. 在输入框中填写完整配置：
ip=10.0.0.6/24,gw=10.0.0.1,ip6=fd88:1::6/64,gw6=fd88:1::1

其中 ip6=fd88:1::6/64 是 sing-box VM 的 IPv6 地址，gw6=fd88:1::1 是下游 ROS 的 LAN IPv6 网关。IPv4 部分分别是该 VM 的 IPv4 地址和 IPv4 网关。保存后点击 PVE 上方的 重新生成镜像（Regenerate Image），再重启虚拟机，让 Cloud-Init 应用新网络配置。

也可以在 PVE Shell 用同一组值设置：

qm set 102 --ipconfig0 ip=10.0.0.6/24,gw=10.0.0.1,ip6=fd88:1::6/64,gw6=fd88:1::1

先创建 sing-box 的 IPv6 路由表（如果已存在就跳过创建），并添加通过 VM 的默认路由：

/routing table add name=sing-box-v6 fib
/ipv6 route add dst-address=::/0 gateway=fd88:1::6 routing-table=sing-box-v6 comment="IPv6 via sing-box VM"

在 ROS 核对 proxy_ipv6 地址列表、mangle 规则和策略路由表：

/ipv6 firewall address-list print detail where list=proxy_ipv6
/ipv6 firewall mangle print detail
/ipv6 route print detail where routing-table=sing-box-v6

只对地址列表匹配的目标标记路由；未匹配目标继续走从上游 RA 学到的 main 表默认路由。若尚无此规则，可添加：

/ipv6 firewall mangle add chain=prerouting action=mark-routing new-routing-mark=sing-box-v6 passthrough=yes dst-address-list=proxy_ipv6 comment="IPv6 proxy destinations via sing-box"

不要添加把所有 LAN IPv6 都标记到 sing-box 的规则，否则原本可以直连的 IPv6 网站也会被送到代理 VM。

如果 sing-box-v6 默认路由不存在，先按当前 RouterOS 版本建立该 routing table，再将默认下一跳指向 fd88:1::6；不要替换 main 表中上游 RA 生成的默认路由。检查 IPv6 forward 防火墙是否允许被标记的策略流量转发到 sing-box VM。添加一条按当前 mangle 路由标记匹配的转发允许规则，并置于最终 drop 之前：

/ipv6 firewall filter add chain=forward action=accept routing-mark=sing-box-v6 comment="Allow IPv6 policy route to sing-box" place-before=[find where comment="IPv6 forward drop remaining"]

不要用“允许 LAN 到 LAN”的宽泛规则代替。

某些代理节点没有 IPv6 出口。此时国内直连 IPv6 网站可以正常打开，但被分流到该节点的境外 IPv6-only 目标可能超时；这不代表 RA 或 NAT66 坏了。可换用支持 IPv6 出口的节点，或让目标按需直连。

9. 最终流量路径

  • RA-only 模式：LAN ULA → 二级 ROS forward 防火墙 → NAT66 → WAN → 上游 ROS → Internet。
  • DHCPv6-PD 模式：LAN 设备使用各自的 GUA → 二级 ROS forward 防火墙 → WAN → Internet，无需 NAT66；WAN 主动入站仍由防火墙默认拦截。
  • 命中 proxy_ipv6 的目标：LAN → 二级 ROS mangle/policy route → sing-box VM；结果取决于当前代理节点是否有 IPv6 出口。

10. 导出、复制和导入 IPv6 配置

在 Terminal 显示命令并复制

在 ROS Terminal 执行：

/ipv6 export terse

命令会在 Terminal 显示 IPv6 菜单下已配置的命令。复制时只需要配置命令行；开头的导出时间、RouterOS 版本等 # 注释不是配置命令。导出默认省略未修改的系统默认值。

导出为文件

如果输出太长不方便从 Terminal 复制，可以直接保存为 .rsc 文件：

/ipv6 export terse file=ipv6-config

之后在 WinBox 打开 Files，下载 ipv6-config.rsc 到电脑。要在另一台 ROS 导入时，把文件上传到目标 ROS 的 Files，再从 Terminal 执行：

/import file-name=ipv6-config.rsc

当前下游 ROS 的实际 IPv6 导出命令

下面是本次从当前下游 ROS 导出的配置命令，设备运行 RouterOS 7.25.1。这里省略了导出头部中的软件 ID；它不是可导入的配置命令。动态学习到的 WAN IPv6 地址和 RA 默认路由也不会出现在静态配置导出中。

**安全提醒：**以下保留的是当时从下游 ROS 导出的原始快照，不是新设备可直接导入的安全模板。快照中包含较宽的 LAN forward accept，且没有完整的 input/forward 默认拒绝规则。新部署请按第 5 节逐条核对并整合；不要直接把这段旧快照导入现网。

/ipv6 address add address=fd88:1::1 comment="LAN ULA for IPv6 NAT66" interface=bridge1
/ipv6 firewall address-list add address=2001:2::/64 list=proxy_ipv6
/ipv6 firewall address-list add address=2001:b28:f23d::/48 list=proxy_ipv6
/ipv6 firewall address-list add address=2001:b28:f23f::/48 list=proxy_ipv6
/ipv6 firewall address-list add address=2001:67c:4e8::/48 list=proxy_ipv6
/ipv6 firewall address-list add address=2001:b28:f23c::/48 list=proxy_ipv6
/ipv6 firewall address-list add address=2a0a:f280::/32 list=proxy_ipv6
/ipv6 firewall filter add action=accept chain=forward in-interface=bridge1
/ipv6 firewall filter add action=accept chain=input in-interface=bridge1
/ipv6 firewall filter add action=accept chain=forward connection-state=established,related,untracked
/ipv6 firewall filter add action=accept chain=input connection-state=established,related
/ipv6 firewall filter add action=drop chain=input connection-state=invalid in-interface=wan
/ipv6 firewall filter add action=accept chain=input comment="Allow upstream IPv6 ND and RA" in-interface=wan protocol=icmpv6 src-address=fe80::/10
/ipv6 firewall filter add action=drop chain=input icmp-options=128:0-255 in-interface=wan protocol=icmpv6
/ipv6 firewall filter add action=drop chain=input icmp-options=137:0-255 in-interface=wan protocol=icmpv6
/ipv6 firewall filter add action=drop chain=input dst-port=53,8291,80,5391 in-interface=wan protocol=tcp
/ipv6 firewall filter add action=drop chain=input dst-port=53,8291,80,5391 in-interface=wan protocol=udp
/ipv6 firewall mangle add action=mark-routing chain=prerouting dst-address-list=proxy_ipv6 new-routing-mark=sing-box-v6
/ipv6 firewall mangle add action=change-mss chain=forward new-mss=clamp-to-pmtu protocol=tcp tcp-flags=syn
/ipv6 firewall mangle add action=change-mss chain=output new-mss=clamp-to-pmtu protocol=tcp tcp-flags=syn
/ipv6 firewall nat add action=masquerade chain=srcnat
/ipv6 nd set [ find default=yes ] disabled=yes
/ipv6 nd add advertise-mac-address=no interface=bridge1 ra-interval=5m-15m
/ipv6 route add dst-address=::/0 gateway=fd88:1::6 routing-table=sing-box-v6
/ipv6 settings set accept-router-advertisements=yes

这段是当前设备配置快照，包含本机的接口名和代理目标列表。不要在原设备上再次导入这些 add 命令，以免生成重复规则。要导入到其他 ROS，先确认接口名 wan、bridge1 存在，并且创建好 /routing table 下的 sing-box-v6 路由表；/ipv6 export 不会导出该路由表定义。建议在 RouterOS 主版本/版本一致的设备间迁移，并先做好目标设备备份。
