二级 RouterOS IPv6 配置：上游 RA、ULA + NAT66 与 sing-box 分流

不使用 DHCPv6-PD，在二级 RouterOS 中通过上游 RA 获取 IPv6 默认路由，向 LAN 发布 ULA，并使用 NAT66 访问 IPv6 网站；同时保留 sing-box 的选择性 IPv6 分流。

本文记录一套二级 RouterOS 的 IPv6 配置：WAN 从上游接收 Router Advertisement（RA）和默认路由；LAN 使用 ULA；由二级 ROS 做 NAT66 出站。这套方案不使用 DHCPv6-PD，也不会让 LAN 设备获得公网 IPv6 入站地址。

1. 网络结构与地址规划

示例网络如下，接口名称和地址按实际环境替换：

设备 / 接口地址说明
上游 ROS → 下游 ROS 的 WANwan下游 ROS 从上游接收 RA
下游 ROS LANbridge1IPv4 网关为 10.0.0.1
下游 ROS LAN IPv6fd88:1::1/64ULA 网关，并向 LAN 发布前缀
Debian sing-box VM10.0.0.6、fd88:1::6/64IPv6 代理下一跳
LAN ULA 前缀fd88:1::/64下游设备的 IPv6 地址

ULA 是内网 IPv6 地址，不能直接在公网路由。NAT66 会在出站时把 LAN 的 ULA 源地址转换成 ROS WAN 上游可路由的 IPv6 源地址。上游必须本身有可用的 IPv6 Internet 出口。

重要： RA 解决的是下游 ROS 如何获知上游路由器和默认路由；它不会自动把公网前缀分配给下游 LAN。没有 DHCPv6-PD 时，采用 ULA + NAT66 是出站访问 IPv6 网站的做法。若需要 LAN 设备拥有可公网路由的 GUA 和公网入站访问，需要上游给出可路由前缀并正确路由给下游。

2. 先备份并检查上游 RA

在下游 ROS 的 Terminal 中执行：

/export file=before-downstream-ipv6
/ipv6 dhcp-client print detail
/ipv6 address print detail
/ipv6 route print detail where dst-address="::/0"
/ipv6 nd print detail

检查 WAN 上是否已通过 RA 获得动态 IPv6 地址和 ::/0 默认路由。此前这套环境的默认路由是从上游 Router Advertisement 学到的，网关显示为上游的 link-local 地址并带有 %wan 接口标记。

RouterOS 开启 IPv6 转发时，请确认它仍接受上游 RA。本环境的 accept-router-advertisements 已为 yes；若显示 yes-if-forwarding-disabled 或 no，可显式设置：

/ipv6 settings set accept-router-advertisements=yes

然后重新检查 WAN 上的动态地址和默认路由。

本文不启用 DHCPv6-PD。若此前尝试用 DHCPv6 pool 给 WAN 或 LAN 分配地址，先核对配置，再禁用那些错误的地址项；不要删除 WAN 上从 RA 获得的动态地址：

/ipv6 dhcp-client disable [find where interface=wan]
/ipv6 address disable [find where from-pool="dhcpv6-ula-pool1"]
/ipv6 address disable [find where from-pool="dhcpv6-gua-pool1"]

如果第一条显示没有匹配项，说明 DHCPv6 client 已关闭。后两条只适用于地址列表中确实存在对应 pool 的情况。

3. 给 LAN 配置 ULA 并发布 RA

在 LAN bridge 上添加 ULA 网关地址：

/ipv6 address add address=fd88:1::1/64 interface=bridge1 advertise=yes comment="LAN ULA for IPv6 NAT66"

让 bridge1 通过 RA 通告前缀。若已有 bridge1 的 ND 项，修改现有项；没有时才用 add 新建，避免重复创建：

/ipv6 nd set [find where interface=bridge1] managed-address-configuration=no other-configuration=no advertise-dns=no

advertise=yes 会让 ROS 把 LAN 上的 fd88:1::/64 前缀放入 RA。客户端会通过 SLAAC 自行生成 ULA 地址，并以 ROS 为默认路由器。不使用 DHCPv6，所以 managed-address-configuration=no。

在客户端重新连接网络或刷新 IPv6 配置后，确认它有 fd88:1::/64 下的地址和 IPv6 默认路由。不要把 link-local 地址 fe80::/10 当作公网地址；它只在本地链路有效。

4. 配置 NAT66 出站

先查看现有 IPv6 NAT：

/ipv6 firewall nat print detail

如果已经有一条无额外匹配条件的 chain=srcnat action=masquerade，它会对 IPv6 出站做 masquerade，本环境已有这条规则，不要重复添加。干净配置中若没有 NAT66，可以添加范围更明确的规则：

/ipv6 firewall nat add chain=srcnat src-address=fd88:1::/64 out-interface=wan action=masquerade comment="NAT66 LAN ULA to upstream IPv6"

确认规则存在且计数会随着 LAN IPv6 流量增长：

/ipv6 firewall nat print stats

这条规则只处理出站源地址转换，不会让公网主动连接进入 LAN。

5. 检查 IPv6 转发防火墙

需要允许从 LAN 转发出去的流量，以及已建立连接的回包。先检查已有规则：

/ipv6 firewall filter print detail

本环境已有 chain=forward action=accept in-interface=bridge1 和 connection-state=established,related,untracked 规则。若你的防火墙没有允许 LAN 转发的规则，应按现有规则顺序补充，并确认 WAN 入站仍由防火墙限制；不要直接清空防火墙或复制不匹配本机策略的整套过滤规则。

6. 给 Proxmox 中的 sing-box VM 配置固定 ULA

本环境的 Debian VM 是 VM 102，IPv4 是 10.0.0.6/24，IPv4 网关是 10.0.0.1。在 Proxmox 的 VM 102 → Cloud-Init → IP 配置（net0）中设置：

ip=10.0.0.6/24,gw=10.0.0.1,ip6=fd88:1::6/64,gw6=fd88:1::1

也可以在 PVE Shell 执行：

qm set 102 --ipconfig0 ip=10.0.0.6/24,gw=10.0.0.1,ip6=fd88:1::6/64,gw6=fd88:1::1

重新生成 Cloud-Init 配置并重启 VM 后，在 Debian 中检查地址和路由：

ip -6 address
ip -6 route
ping -6 -c 4 fd88:1::1

其中 fd88:1::6 是 sing-box VM 的固定 LAN IPv6 地址，供 ROS 的 sing-box IPv6 路由表作为下一跳。仅做 ULA + NAT66 的普通 LAN 出站访问并不要求安装 sing-box。

7. 保留 sing-box 的选择性 IPv6 分流

这套配置只将 ROS IPv6 地址列表 proxy_ipv6 中的目标送往 sing-box，其余 IPv6 目标仍使用 ROS 从上游 RA 学到的主路由表默认路由。检查现有配置：

/ipv6 firewall address-list print detail where list=proxy_ipv6
/ipv6 firewall mangle print detail
/ipv6 route print detail where routing-table=sing-box-v6

选择性分流规则应类似：

/ipv6 firewall mangle add chain=prerouting action=mark-routing new-routing-mark=sing-box-v6 passthrough=yes dst-address-list=proxy_ipv6 comment="IPv6 proxy destinations via sing-box"

若规则已经存在，不要再添加一条重复规则。sing-box 的路由表默认路由下一跳应为 Debian VM 的 ULA：

/ipv6 route set [find where dst-address="::/0" and routing-table="sing-box-v6"] gateway=fd88:1::6

确认输出中该路由为 active，且 immediate-gw 显示 fd88:1::6%bridge1。如果该路由尚不存在，则先检查并创建 sing-box-v6 路由表，再添加默认路由；不要在 main 表中替换上游 RA 学到的默认路由。

不要把所有 LAN IPv6 流量都无条件标记到 sing-box。 本环境曾添加过一条名为 IPv6 LAN to sing-box 的全量分流规则，导致原本应通过 NAT66 直连的 IPv6 网站也被送到代理 VM。检查并停用它：

/ipv6 firewall mangle disable [find where comment="IPv6 LAN to sing-box"]

IPv4 的 sing-box 分流规则不需要因为本篇 IPv6 配置而修改。

8. 按顺序验证

先从 ROS 验证上游 IPv6 出口：

/ping address=2606:4700:4700::1111 count=4

再验证 LAN ULA 经过 ROS 出口访问 IPv6。RouterOS 本机 ping 测试：

/ping address=2606:4700:4700::1111 src-address=fd88:1::1 count=4

本环境在配置完成后返回 4/4 echo reply，说明 ROS 的 IPv6 默认路由可用。最后必须从实际 LAN 客户端验证，而不能只看 ROS 自己的 ping：

curl -6 --connect-timeout 8 https://api64.ipify.org

若成功，会返回一个公网 IPv6 地址（通常是上游分配给 WAN 的地址）；若提示无法连接，再依次检查客户端是否获得 ULA 和默认路由、NAT66 计数是否增长、IPv6 forward 规则是否允许，以及该目标是否被 proxy_ipv6 列表匹配。

浏览器 IPv6 测试网站也可用于确认客户端能否通过 IPv6 访问，但测试网站未检测到 IPv6 时，不能仅凭这一项区分网络故障与浏览器扩展/代理过滤。先用上面的 curl -6 得到客户端层面的结果。

9. 配置结果与边界

最终流量路径如下：

  • 一般 IPv6 网站：LAN ULA → 下游 ROS NAT66 → 上游 ROS → Internet。
  • proxy_ipv6 地址列表中的目标：LAN → 下游 ROS 标记路由 → fd88:1::6 sing-box VM。
  • IPv4：继续沿用已有的 IPv4 sing-box 配置。

ULA + NAT66 提供的是出站 IPv6 访问能力，不等同于下游 LAN 获得可公网路由的 IPv6 前缀。若希望每台客户端都拥有全球单播地址并可接受公网入站连接，需要上游网络提供并路由可用前缀（例如 DHCPv6-PD），或由上游管理员另行配置路由；仅靠 ND 无法跨路由器传递前缀。
