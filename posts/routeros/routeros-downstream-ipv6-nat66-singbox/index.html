二级 RouterOS IPv6 配置：上游 RA、ULA + NAT66 与 sing-box 分流

从新装二级 RouterOS 开始配置 IPv6：检查上游 RA，设置 LAN ULA 和 SLAAC、NAT66、IPv6 防火墙，并逐步验证直连及可选的 sing-box 分流。

本文按一台已经完成 IPv4 上网、准备首次启用 IPv6 的二级 RouterOS编写，从检查上游到配置 LAN、防火墙和验证逐步操作。方案不使用 DHCPv6-PD：二级 ROS 的 WAN 通过上游 Router Advertisement（RA）学习 IPv6 默认路由；LAN 使用 ULA，由二级 ROS 执行 NAT66 后访问 IPv6 网站。

这套配置提供 LAN 主动访问 IPv6 Internet 的能力，不会让 LAN 设备获得公网可入站的 GUA 前缀。若需要每台设备拥有公网 IPv6 地址并接受公网入站连接，上游必须把可路由的 IPv6 前缀委派或静态路由给下游；单靠 ND/RA 不能跨路由器转发上游前缀。

1. 网络结构与替换项

本文沿用当前环境的 LAN 地址规划。示例接口名 ether1、bridge1 必须替换成你的实际 WAN、LAN 接口名；不要把命令原样套到接口名不同的 ROS 上。

设备 / 接口示例配置说明
上游 ROS 的下游口接入下游 WAN 的二层网段在该接口上发布上游 IPv6 RA
二级 ROS WANether1从上游 RA 学到 IPv6 地址/默认路由
二级 ROS LANbridge1，IPv4 网关 10.0.0.1/24LAN bridge，成员端口按现有 IPv4 配置
二级 ROS LAN IPv6fd88:1::1/64ULA 网关并发布 SLAAC 前缀
LAN IPv6 前缀fd88:1::/64客户端自动生成的内网 IPv6 地址

fd88:1::/64 是本文环境采用的示例 ULA。ULA 只在内网使用，不会由公网路由；请先确认没有和现有隧道或其他 LAN 前缀冲突。若网络已有自己的 ULA，就统一替换下文的前缀和网关地址。

开始前先在下游 ROS Terminal 备份并确认接口名称：

/export file=before-ipv6
/interface print detail
/interface list member print detail
/ipv6 settings print
/ipv6 firewall filter print detail
/ipv6 firewall nat print detail

建议通过 WinBox 的 Safe Mode 或在本地 LAN 侧操作，避免接口、RA 或防火墙设置错误后失去管理连接。本文只配置 IPv6，不更改已有 IPv4 地址、DHCP、NAT 或 IPv4 防火墙。

2. 先确认上游 ROS 正在发布 IPv6 RA

二级 ROS WAN 所在的上游网段必须有可用 IPv6 出口。上游 ROS 应在连接二级 ROS WAN 的接口上配置了可用 IPv6 地址，并在该接口启用 Neighbor Discovery / Router Advertisement。先在上游检查：

/ipv6 address print detail
/ipv6 nd print detail
/ipv6 route print detail where dst-address="::/0"

上游要能访问 IPv6 Internet，并在连接下游的接口上发布 RA。若上游本身没有可用的 IPv6 默认路由，先修好上游；下游无法凭空产生 IPv6 出口。

上下游 ROS 之间的 RA 负责告诉二级 ROS“上游路由器是谁、默认路由在哪里”。它不等于 DHCPv6-PD，也不会把一段可公网路由的前缀交给二级 ROS LAN。

3. 让二级 ROS WAN 接收上游 RA

在下游 ROS 检查动态地址和默认路由：

/ipv6 address print detail
/ipv6 route print detail where dst-address="::/0"
/ipv6 nd print detail

开启 IPv6 转发的路由器默认可能拒绝 RA。二级 ROS 必须允许从 WAN 接收上游 RA：

/ipv6 settings set accept-router-advertisements=yes

RouterOS 官方文档提示，修改 IPv6 Settings 后需要重启才能应用；如果之前此项不是 yes，保存配置后重启，再检查 /ipv6 address print detail 和 ::/0 路由。期望看到 WAN 上动态学习到的 IPv6 地址，以及网关为上游 link-local 地址并带 WAN 接口标识的活动默认路由，例如 fe80::...%ether1。

如果 WAN 上仍只有 fe80:: link-local 地址、没有动态 IPv6 地址或默认路由，先检查上游 RA 是否到达、上游连接下游的 ND 配置、二级 ROS WAN 接口名和接口/VLAN 连接；不要继续配置 NAT66，直到二级 ROS 本机已具备上游 IPv6 路由。

4. 给 LAN 配置 ULA 网关和 RA/SLAAC

先确认没有同一地址或前缀的旧配置：

/ipv6 address print detail
/ipv6 nd print detail
/ipv6 nd prefix print detail

如果没有 fd88:1::1/64，在 LAN bridge 添加地址并开启前缀通告：

/ipv6 address add address=fd88:1::1/64 interface=bridge1 advertise=yes comment="LAN ULA gateway"

advertise=yes 会让 RouterOS 在该接口的 RA 中通告 fd88:1::/64。客户端通过 SLAAC 自动生成 ULA 地址，并把 ROS 作为 IPv6 默认路由器。这里不运行 DHCPv6 Server，因此 RA 的 managed-address-configuration 和 other-configuration 都保持 no。

确认 LAN bridge 有 ND 项。若已有 interface=bridge1 的项目，修改它；若没有才新增。不要在 WAN 接口发布 LAN 的 RA：

/ipv6 nd set [find where interface=bridge1] managed-address-configuration=no other-configuration=no advertise-dns=no

如果上一条报没有匹配项，改为：

/ipv6 nd add interface=bridge1 managed-address-configuration=no other-configuration=no advertise-dns=no comment="Advertise LAN ULA"

在 /ipv6 nd print detail 中确认用于发布 RA 的接口只有 LAN bridge。若看到 interface=all 或 WAN 上的 ND/RA 项，先核对其用途并调整，避免把内网前缀错误发布到上游。客户端重新连接网络或刷新 IPv6 配置后，应获得 fd88:1::/64 地址和 IPv6 默认路由。

5. 添加 NAT66 出站规则

先确保二级 ROS WAN 有上游可用的 IPv6 地址和活动 ::/0 路由，然后查看现有 IPv6 NAT：

/ipv6 firewall nat print detail

如果已有作用范围合适的 IPv6 srcnat / masquerade 规则，不要重复添加。若没有，在 IPv6 NAT 表增加只转换本 LAN ULA 的规则：

/ipv6 firewall nat add chain=srcnat src-address=fd88:1::/64 out-interface=ether1 action=masquerade comment="NAT66 LAN ULA to upstream"

这里的 ether1 要替换为 WAN 接口。NAT66 将 LAN 的 ULA 源地址转换成 WAN 上可用的 IPv6 源地址，使上游能够把回包送回二级 ROS。它只用于出站连接，不提供公网主动连接到 LAN 的能力。

6. 配置 IPv6 防火墙

IPv6 没有 IPv4 那种依赖 NAT 隐藏内网的默认保护。必须限制路由器自身的 WAN 管理访问，并禁止 WAN 发起到 LAN 的新连接。IPv6 ICMP（ICMPv6）不能一概屏蔽：邻居发现、错误回报和 Path MTU Discovery 都依赖它。

先看现有规则：

/ipv6 firewall filter print detail

以下规则适用于IPv6 filter 表为空或已确认能按此顺序整合的配置。如果表里已有规则，先确认没有更早命中的宽泛 drop；不要盲目重复粘贴，也不要为了套用示例而清空现有防火墙。每条规则按顺序添加，确认在同一 chain 中的顺序如下：

/ipv6 firewall filter
add chain=input action=accept connection-state=established,related,untracked comment="IPv6 input established related"
add chain=input action=drop connection-state=invalid comment="IPv6 input drop invalid"
add chain=input action=accept protocol=icmpv6 comment="IPv6 input allow ICMPv6"
add chain=input action=accept in-interface=bridge1 comment="IPv6 input allow LAN management"
add chain=input action=drop in-interface=ether1 comment="IPv6 input block other WAN access"
add chain=input action=drop comment="IPv6 input drop remaining"
add chain=forward action=accept connection-state=established,related,untracked comment="IPv6 forward established related"
add chain=forward action=drop connection-state=invalid comment="IPv6 forward drop invalid"
add chain=forward action=accept in-interface=bridge1 out-interface=ether1 comment="IPv6 forward LAN to WAN"
add chain=forward action=drop comment="IPv6 forward drop remaining"

将 bridge1 和 ether1 替换为 LAN 和 WAN。规则作用：

  • input 允许已有连接、ICMPv6 和 LAN 管理流量；WAN 到路由器的其他访问以及其余未匹配流量都会被丢弃。
  • forward 允许连接回包和 LAN 主动发往 WAN 的流量；没有允许 WAN 发起到 LAN 的新连接，因此公网不能直接探测 LAN 设备。
  • 若有多个 LAN/VLAN，应分别添加允许的 LAN 到 WAN 规则，不要把 WAN 加入 LAN 范围。

检查最终规则及顺序：

/ipv6 firewall filter print detail

如果把防火墙规则加在了已有 drop 规则后面，新增的允许规则不会生效；请在 WinBox 中将它们移动到相应 chain 的 drop 之前。

7. 按层验证 IPv6

7.1 验证下游 ROS 的上游路由

/ipv6 address print detail
/ipv6 route print detail where dst-address="::/0"
/ping address=2606:4700:4700::1111 count=4

先确认默认路由状态为 active，再检查 ping。若路由缺失或本机不能访问 IPv6，问题还在上游 RA/路由，暂时不用排查 LAN NAT66。

7.2 验证 LAN 客户端地址和出站

在 Mac/Linux 客户端检查 IPv6 地址和默认路由，再直连 IPv6-only 测试接口：

ifconfig
route -n get -inet6 default
curl --noproxy '*' -6 --connect-timeout 8 https://api6.ipify.org

Linux 可用 ip -6 address 和 ip -6 route 查看地址、路由。api6.ipify.org 只提供 IPv6；成功应返回公网 IPv6 地址。与此同时观察 NAT66 计数：

/ipv6 firewall nat print stats
/ipv6 firewall filter print stats

逐项判断：

  1. 客户端没有 fd88:1::/64 地址：检查 LAN ULA 地址、ND 项、RA 是否在正确 bridge 上发布，并重连客户端。
  2. 客户端有 ULA 但没有 IPv6 默认路由：检查 LAN RA 和 ND 项，确认没有 RA lifetime 为 0 的配置。
  3. ROS 本机没有活动 ::/0 或无法 ping IPv6 地址：回到第 2、3 节检查上游 RA 和出口。
  4. ROS 本机正常、客户端失败：检查 forward 允许规则顺序、NAT66 匹配接口和计数器，以及是否有更早的 drop。
  5. 使用 api64.ipify.org 得到 IPv4：这个接口可能在透明代理场景返回代理节点的 IPv4 出口；用 IPv6-only 的 api6.ipify.org 判断真正的 IPv6 直连能力。curl --noproxy '*' 只绕过 Mac 上 curl 的显式代理，不能跳过 ROS 的透明分流规则。

某一个 IPv6 字面地址或网站打不开，不足以证明 IPv6 整体故障。目标可能没有开放 HTTP/80、服务端未响应，或该目标被 policy routing 发往没有 IPv6 出口的代理节点。应先用 IPv6-only 测试接口和已知可用的 IPv6 网站判断链路，再排查具体目标。

8. 可选：保留 sing-box 的 IPv6 选择性分流

只在已经配置并需要通过 sing-box 代理特定 IPv6 目标时执行本节。普通 LAN IPv6 直连和 NAT66 不依赖 sing-box。

本环境 Debian VM 使用 10.0.0.6、ULA fd88:1::6/64，ROS LAN 网关为 fd88:1::1。如果要让它承担 IPv6 下一跳，在 PVE VM 102 的 Cloud-Init 设置静态 IPv6：

qm set 102 --ipconfig0 ip=10.0.0.6/24,gw=10.0.0.1,ip6=fd88:1::6/64,gw6=fd88:1::1

先创建 sing-box 的 IPv6 路由表（如果已存在就跳过创建），并添加通过 VM 的默认路由：

/routing table add name=sing-box-v6 fib
/ipv6 route add dst-address=::/0 gateway=fd88:1::6 routing-table=sing-box-v6 comment="IPv6 via sing-box VM"

在 ROS 核对 proxy_ipv6 地址列表、mangle 规则和策略路由表：

/ipv6 firewall address-list print detail where list=proxy_ipv6
/ipv6 firewall mangle print detail
/ipv6 route print detail where routing-table=sing-box-v6

只对地址列表匹配的目标标记路由；未匹配目标继续走从上游 RA 学到的 main 表默认路由。若尚无此规则，可添加：

/ipv6 firewall mangle add chain=prerouting action=mark-routing new-routing-mark=sing-box-v6 passthrough=yes dst-address-list=proxy_ipv6 comment="IPv6 proxy destinations via sing-box"

不要添加把所有 LAN IPv6 都标记到 sing-box 的规则，否则原本可以直连的 IPv6 网站也会被送到代理 VM。

如果 sing-box-v6 默认路由不存在，先按当前 RouterOS 版本建立该 routing table，再将默认下一跳指向 fd88:1::6；不要替换 main 表中上游 RA 生成的默认路由。检查 IPv6 forward 防火墙是否允许被标记的策略流量转发到 sing-box VM。添加一条按当前 mangle 路由标记匹配的转发允许规则，并置于最终 drop 之前：

/ipv6 firewall filter add chain=forward action=accept routing-mark=sing-box-v6 comment="Allow IPv6 policy route to sing-box" place-before=[find where comment="IPv6 forward drop remaining"]

不要用“允许 LAN 到 LAN”的宽泛规则代替。

某些代理节点没有 IPv6 出口。此时国内直连 IPv6 网站可以正常打开，但被分流到该节点的境外 IPv6-only 目标可能超时；这不代表 RA 或 NAT66 坏了。可换用支持 IPv6 出口的节点，或让目标按需直连。

9. 最终流量路径

  • 一般 IPv6 目标：LAN ULA → 二级 ROS IPv6 forward 防火墙 → NAT66 → 二级 ROS WAN → 上游 ROS → Internet。
  • 命中 proxy_ipv6 的目标：LAN → 二级 ROS mangle/policy route → sing-box VM；结果取决于当前代理节点是否有 IPv6 出口。
  • 未配置 DHCPv6-PD 时，LAN 设备使用 ULA，不拥有公网可路由的 GUA，也不能直接接受公网 IPv6 入站连接。
