03 RouterOS 配置 FakeIP

RouterOS 配置 FakeIP 。

本文介绍使用FakeIP分流法，实现局域网内设备透明代理中，主路由部分的设置#

sing-box及mosdns的使用方法不在本文讨论范围内

**安装前先检查 sing-box 主机的系统 DNS：**在 PVE 的 sing-box 虚拟机 Cloud-Init 中，DNS 服务器应填写返回真实 IP 的上游（例如 223.5.5.5），不要填写虚拟机自己的 IP。局域网客户端可以使用 sing-box DNS，但主机自身若使用它，github.com 等域名可能解析为 28.0.0.0/8 内的 FakeIP，使安装、重装依赖 sing-box 和 RouterOS 的 FakeIP 路由。已运行的虚拟机修改 PVE 设置后，还应在系统内检查；重生成镜像并重启不一定会覆盖已有的网络配置：

cat /etc/resolv.conf
getent ahostsv4 github.com | head -n 1

nameserver 应为真实上游，解析结果不应落在 FakeIP 网段；否则先修正虚拟机内的系统 DNS，再安装 sing-box。

1. 三种方案总览#

  • 默认sing-box的ipv4为10.0.0.2，ipv6为dc00::2222，Fake v4网段为28.0.0.0/8，Fake v6网段为f2b0::/18。 特别注意：ros开启fasttrack，mangle会失效，只能采取route的方式路由fakeip

小tips：添加完下方的proxy_ipv4和proxy_ipv6列表后，在源地址伪装中排除掉目标地址是代理列表的IP，即可实现在代理程序（sing-box或mihomo）中正确显示连接的源IP

/ipv6 route add dst-address=::/0 gateway=dc00::2222 routing-table=sing-box-v6
  • 添加路由规则确保fakev6路由正常执行
/routing rule add action=lookup-only-in-table comment= "for ipv6 mangle effective in route"

2. 方案二：通过 /ip route 直接添加路由#

  • 下面命令未包含TG IP、奈菲IP，需要用可自行添加。此方法与第1种mangle标记法不冲突，例如可以FakeIP使用route，TG IP等依然使用mangle。

IPv4 部分#

/ip route add disabled=no dst-address=28.0.0.0/8 gateway=10.0.0.2 routing-table=main suppress-hw-offload=no
/ip route add disabled=no distance=1 dst-address=8.8.8.8/32 gateway=10.0.0.2 routing-table=main scope=30 suppress-hw-offload=no target-scope=10

IPv6 部分#

2026-11-18 补充：新 FakeIP 地址池与 RouterOS 7 一次配置#

以下是本站后续实测的补充，上面的原文和旧地址示例均保留。新装时在三种旧方案与本节之间选择一套，不要把两套命令一起导入。本文的 sing-box 安装包默认仍可能使用 28.0.0.0/8 和 2001:2::/64；本节的新地址需要先在 Rule UI 中主动设置，不能只改 RouterOS。

先核对五个本地参数#

下面的 RouterOS 7 导入文件 使用原文的示例地址。导入前先下载并用纯文本编辑器核对、替换：

参数文件中的示例应替换为
LAN 接口bridge1客户端所在的 RouterOS LAN bridge
LAN 网段10.0.0.0/24客户端实际 IPv4 网段
RouterOS LAN IPv410.0.0.1该 bridge 上的 RouterOS IPv4
sing-box LAN IPv410.0.0.2sing-box 的固定 IPv4
sing-box LAN IPv6dc00::2222RouterOS 能到达的 sing-box ULA IPv6

先从 RouterOS 确认 10.0.0.2 和 dc00::2222（或你替换后的地址）都可达，再在 Rule UI 的 FakeIP 设置中把 IPv4 地址池设为 198.18.0.0/15，IPv6 地址池设为 2001:2::198:18:0:0/96，保存并确认 sing-box 能启动。两个地址池必须与 RouterOS 下发的路由完全一致。客户端 DNS 指向 sing-box 的 LAN 地址；sing-box 宿主机的系统 DNS 继续使用返回真实 IP 的解析器，不能指向自己的 FakeIP DNS。没有域名或证书的新装环境可以使用内网 IP 访问管理页。

备份、试导入、正式导入#

把编辑好的 .rsc 文件通过 WinBox Files 上传到 RouterOS。在 RouterOS Terminal 执行：

/export file=before-sb-fakeip-19818
/import file-name=singbox-fakeip-19818-routeros7.rsc verbose=yes dry-run
/import file-name=singbox-fakeip-19818-routeros7.rsc verbose=yes

dry-run 需要支持该参数的 RouterOS 7 版本；如提示不支持，先升级 RouterOS 再导入。正式导入时建议打开 WinBox Safe Mode，确认 LAN 与代理都正常后再退出 Safe Mode。文件按全新配置编写，只导入一次；已经使用上文任一方案的路由器不要重复导入同名路由表和路由规则。RouterOS 的 import 会逐条执行，发生错误时应按报错行检查，不能把部分导入当成成功。

导入文件会建立 IPv4、IPv6 路由表及指向 sing-box 的下一跳；将两个 FakeIP 网段和四个公共 DNS IPv4 地址路由到 sing-box；在 Drop invalid forward 之前放行仅限 LAN→LAN、目标为 FakeIP 的 invalid 流量；文件不增加 NAT 规则。若你还有 Telegram 等直连 IP 段要强制代理，按上文为实际需要的网段另加路由规则。

逐条输入的 RouterOS 命令#

不使用 .rsc 文件时，先按上文备份，并把下面的示例接口、网段和地址替换成自己的值，再在 RouterOS Terminal 按顺序执行。下面与导入文件是同一套配置，两种方式只选一种，不要重复执行。

# RouterOS 7 新装示例。先按文章核对 bridge1、10.0.0.0/24、10.0.0.1、10.0.0.2、dc00::2222。
# 仅导入一次；已有同名路由表或路由规则时，按文章的迁移步骤修改原规则。
# sing-box 的 FakeIP 地址池须先设置为 198.18.0.0/15 和 2001:2::198:18:0:0/96。

/routing table add fib name=sing-box-v4
/routing table add fib name=sing-box-v6
/ip route add dst-address=0.0.0.0/0 gateway=10.0.0.2 routing-table=sing-box-v4 comment="SB FakeIP example v4 gateway"
/ipv6 route add dst-address=::/0 gateway=dc00::2222 routing-table=sing-box-v6 comment="SB FakeIP example v6 gateway"
/routing rule add action=lookup dst-address=198.18.0.0/15 table=sing-box-v4 comment="SB FakeIPv4 198.18/15"
/routing rule add action=lookup dst-address=2001:2::198:18:0:0/96 table=sing-box-v6 comment="SB FakeIPv6 /96"
/routing rule add action=lookup dst-address=1.1.1.1/32 table=sing-box-v4 comment="SB DNS 1.1.1.1"
/routing rule add action=lookup dst-address=1.0.0.1/32 table=sing-box-v4 comment="SB DNS 1.0.0.1"
/routing rule add action=lookup dst-address=8.8.8.8/32 table=sing-box-v4 comment="SB DNS 8.8.8.8"
/routing rule add action=lookup dst-address=8.8.4.4/32 table=sing-box-v4 comment="SB DNS 8.8.4.4"

# 必须排在现有的 Drop invalid forward 前，防止 FakeIP TCP 握手被丢弃。
/ip firewall filter add chain=forward action=accept connection-state=invalid dst-address=198.18.0.0/15 in-interface=bridge1 out-interface=bridge1 place-before=0 comment="SB allow invalid LAN FakeIPv4"
/ipv6 firewall filter add chain=forward action=accept connection-state=invalid dst-address=2001:2::198:18:0:0/96 in-interface=bridge1 out-interface=bridge1 place-before=0 comment="SB allow invalid LAN FakeIPv6"

DNS 查询边界#

四个公共 DNS IPv4 地址的路由规则沿用原方案，UDP 和 TCP 请求都会被送到 sing-box 主机；这里不增加把 TCP/53 改写到本地 DNS 的 hairpin NAT。TCP 请求后续是否由 TProxy 捕获、使用哪个出站，取决于 sing-box 规则，不能以这些公共地址的查询结果判断本地 FakeIP 是否生效。需要本地 TCP DNS 返回 FakeIP 的客户端，应直接查询 sing-box 的 LAN DNS 地址，例如 dig +tcp @10.0.0.2 example.com A。境外 DNS 上游是否经过代理，仍由 Rule UI 中的 DNS 配置决定。

IPv6 客户端同样需要把 2001:2::198:18:0:0/96 路由到 sing-box，并让 RouterOS 的 IPv6 forward 规则允许这个 FakeIP 段。上述四个公共 DNS 地址都是 IPv4，不覆盖 IPv6 DNS、DoH 或 DoT。

已装旧方案如何迁移#

不要导入新装文件。先在 RouterOS /routing rule print detail、/ip firewall address-list print detail、/ipv6 firewall address-list print detail、/ip firewall filter print detail 和 /ipv6 firewall filter print detail 中找到旧 FakeIP 项。先添加新 IPv4、IPv6 FakeIP 路由，并核对下一跳指向 sing-box；再核对新网段的 invalid 放行规则排在 Drop invalid forward 之前。若原有 IPv6 放行规则覆盖整个 2001:2::/64，它已覆盖新 /96，可以保留。确认新路由准备好以后，再切换 Rule UI 的 FakeIP 地址池；验收后删除旧网段的路由和不再需要的放行规则。不同地址池自动使用独立的 FakeIP 缓存，回退地址池时会重新使用旧缓存；切换期间客户端缓存的旧地址仍可能短暂失效。

验收时，在客户端向 sing-box 的 LAN DNS 地址查询 A、AAAA 记录，并检查 198.18.0.0/15 与 IPv6 FakeIP 的透明连接。DNS 返回 FakeIP 只能证明本地解析与地址池一致；还应实际打开网页、播放视频，并检查 sing-box 节点与 RouterOS 规则计数器。若拿到 FakeIP 后 TCP 连接缓慢，优先检查 invalid 放行规则及其顺序。
