03 RouterOS 配置 FakeIP

RouterOS 配置 FakeIP 。

本文介绍使用FakeIP分流法，实现局域网内设备透明代理中，主路由部分的设置

sing-box及mosdns的使用方法不在本文讨论范围内

1. 三种方案总览

  • 以下示例假设 sing-box 的 IPv4 为 10.0.0.2、IPv6 为 dc00::2222，FakeIP 网段为 28.0.0.0/8 和 f2b0::/18；请按自己的网关地址替换示例中的下一跳。 特别注意：ros开启fasttrack，mangle会失效，只能采取route的方式路由fakeip

公版一键安装用户先对齐 FakeIP： IPv4 默认 28.0.0.0/8 与本文一致；IPv6 默认 2001:2::/64 与本文的 f2b0::/18 不同。先安装 sing-box 网关，在 Rule UI 的 FakeIP 设置中把 IPv6 网段改为 f2b0::/18 并保存，再确认网关实际 IPv4、IPv6 地址，最后配置 RouterOS。若仍使用安装默认的 IPv6 网段，应在 RouterOS 中将下文所有 f2b0::/18 替换为实际设置值。不要把 FakeIP 网段加入灰名单。

下文三个方案的基础规则对应公版初装：FakeIP 和灰名单预装的 Google、Cloudflare 公共 DNS 地址（IPv4、IPv6 各 4 个）。其余网段是按需示例，不能整段照抄。当前 RouterOS 的 58 条目标规则中没有这 4 个 DNS IPv6 地址；本文为对齐公版灰名单额外补齐它们。历史文章把其中 26 段归为 Netflix 相关，RouterOS 规则本身没有用途标注，使用前应核实归属。Apple APNs 网段来自Apple 官方文档；Telegram 官方网段见其CIDR 列表。

只选一种方案。 RouterOS 把目标送到网关后，sing-box 还要接管它：FakeIP 自动接管，灰名单预装的 DNS 地址自动捕获，启用 Telegram IP 捕获时其官方 CIDR 由程序维护。其它真实 IP/CIDR 若要强制代理，必须同时加入 Rule UI 灰名单和 RouterOS 对应方案；95.161.64.0/20 不在 Telegram 当前官方列表中。Apple 域名在公版白名单中优先直连，强制代理 APNs 前还需检查白名单。末尾两条 /32 是本站旧教程中的可选示例，新用户无需添加：45.12.89.152 曾用于把 upgrade.mikrotik.com、licence.mikrotik.com 静态解析到该地址；104.19.192.175 曾用于把 api.cloudflare.com 静态解析到该地址，让 RouterOS DDNS 脚本经代理访问。当前 RouterOS 仍有这两条路由，但未查到对应静态 DNS 记录；若域名没有解析到这些 IP，路由就不会命中。只有确认自己仍使用相同固定解析、且确需经网关访问时，才考虑添加。

小tips：添加完下方的proxy_ipv4和proxy_ipv6列表后，在源地址伪装中排除掉目标地址是代理列表的IP，即可实现在代理程序（sing-box或mihomo）中正确显示连接的源IP

3. 方案三：通过 /routing rule 添加路由规则（博主目前在用此法）

  • 添加sing-box-v4、sing-box-v6路由表
/routing table add name=sing-box-v4 fib
/routing table add name=sing-box-v6 fib
  • 设置路由表sing-box-v4、sing-box-v6的下一跳网关为sing-box
/ip route add dst-address=0.0.0.0/0 gateway=10.0.0.2 routing-table=sing-box-v4
/ipv6 route add dst-address=::/0 gateway=dc00::2222 routing-table=sing-box-v6
  • 基础路由规则：FakeIP 和公版灰名单中的公共 DNS
/routing rule
add action=lookup dst-address=f2b0::/18 table=sing-box-v6
add action=lookup dst-address=28.0.0.0/8 table=sing-box-v4
add action=lookup dst-address=1.1.1.1/32 table=sing-box-v4
