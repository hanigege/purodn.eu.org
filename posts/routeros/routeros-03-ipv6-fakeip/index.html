03 RouterOS 配置 FakeIP

让 RouterOS 将 FakeIP 和预装灰名单目标路由到 sing-box 网关。

本文使用 RouterOS 主路由和独立的 sing-box 网关。客户端仍以 RouterOS 为默认网关，DNS 指向 sing-box；RouterOS 只把需要接管的目标路由到 sing-box。适用于 singbox-ui-alpine、singbox-ui-alpine-1.14 和 singbox-ui-debian13 的新装默认规则。

安装前核对

  1. 先在 Rule UI 配置可用代理节点，并确认网关服务正常。
  2. 确认 sing-box 的内网 IPv4 和 RouterOS 可达的 IPv6 ULA。下文 10.0.0.2、fd00::2 只是示例，必须替换为自己网关的地址。
  3. 确认 Rule UI 显示的 FakeIP 网段。三个仓库新装默认均为 IPv4 28.0.0.0/8、IPv6 2001:2::/64。若已修改，下面的路由目标必须同步替换。
  4. 确认 sing-box 网关本身以 RouterOS 为正常上游，并让客户端通过该网关查询 DNS。仅配置 DNS、不配置 FakeIP 路由，客户端拿到 FakeIP 后仍无法连通。

IPv6 FakeIP 路由的下一跳使用网关实际可达的 IPv6 地址，并不要求代理节点本身有 IPv6 地址。节点或其远端若不能访问真实 IPv6 目标，不要据此把真实公网 IPv6 网段也强制送代理；本地 IPv6 直连仍可走 RouterOS 的正常路由。

推荐：在主路由表添加目标路由

新装只需将两个 FakeIP 网段送到 sing-box。命令在 RouterOS 7 的 Terminal 执行；先替换示例下一跳，再逐条添加。

/ip route add dst-address=28.0.0.0/8 gateway=10.0.0.2 comment="sing-box FakeIP IPv4"
/ipv6 route add dst-address=2001:2::/64 gateway=fd00::2 comment="sing-box FakeIP IPv6"

预装灰名单还包含四个公共 DNS 的 IPv4 地址。为让客户端直接访问这些地址时也进入代理，继续添加以下路由；它们与预装灰名单一一对应。

/ip route add dst-address=1.1.1.1/32 gateway=10.0.0.2 comment="sing-box DNS IPv4"
/ip route add dst-address=1.0.0.1/32 gateway=10.0.0.2 comment="sing-box DNS IPv4"
/ip route add dst-address=8.8.8.8/32 gateway=10.0.0.2 comment="sing-box DNS IPv4"
/ip route add dst-address=8.8.4.4/32 gateway=10.0.0.2 comment="sing-box DNS IPv4"

若 RouterOS 已开启 FastTrack，使用上述主路由表中的目标路由即可；不要再为同一目标叠加 mangle 或 /routing rule。如主路由上有对发往 sing-box 网关流量的 srcnat，应按实际规则排除它，以便网关看到客户端真实源地址。调整防火墙前先核对现有规则顺序和回程连接放行情况。

按需添加真实 IP 目标

FakeIP 路由只处理 DNS 返回的 FakeIP。需要接管应用直接访问的真实 IP/CIDR 时，先把目标加入 Rule UI 的灰名单，再在 RouterOS 添加同一目标、同一地址族的路由。两侧必须一致；如果 sing-box 把目标判为 direct，而 RouterOS 又把该目标送回 sing-box，可能形成路由回环。

例如要代理某个真实 IPv4 地址，先在灰名单加入该地址，再添加指向 sing-box 的 /32 路由；不要把 FakeIP 网段重复加入灰名单。

对真实 IPv6 目标采用同样方法前，先验证所选代理节点能访问该 IPv6 目标。公共 DNS 的 IPv6 地址、Apple APNs、Netflix 和 Telegram 的真实 IP 段均不属于新装基础规则；不要直接复制旧教程中的整批固定网段。Telegram IP 捕获可在 Rule UI 按需启用，RouterOS 若需路由其真实 IP，应以 Telegram 官方 CIDR 列表为准并保持同步。

预装白名单不再对所有 Apple 域名作泛匹配直连。Apple 流量仍按内置的中国大陆域名、IP 和其它分流规则处理；若自行添加 Apple 真实 IP 路由，应再次检查网关中的白名单与直连规则。Syncthing 等自建服务也不预置公网 IP 或端口：需要 IPv6 直连时，保留对等设备真实 IPv6 的正常路由，并只对实际运行 Syncthing 的主机开放所需入站端口。

验证

/ip route print detail where comment~"sing-box"
/ipv6 route print detail where comment~"sing-box"

确认路由处于 active 状态、下一跳正确，再从客户端查询 DNS 并访问一个返回 FakeIP 的域名，检查 sing-box 连接记录是否出现该客户端。分别验证一个应代理的域名和一个本地 IPv6 直连目标；如果没有连接记录，先检查客户端 DNS、FakeIP 实际网段、RouterOS 路由及网关 TProxy 状态。
